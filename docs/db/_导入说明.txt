导出命令
------------------------------------------------
mysqldump -uroot -p -h127.0.0.1 -P3306 \
  --default-character-set=utf8mb4 --single-transaction --quick --hex-blob \
  --routines --triggers --events --add-drop-table twelvet-fast \
  > docs/db/twelvet-fast_2026-11-03.sql

参数说明：
  --single-transaction  一致性快照，不锁表（InnoDB），导出期间业务可继续写入
  --hex-blob            BLOB/二进制字段以十六进制写出，避免编码损坏
  --routines/triggers/events  一并导出存储过程、触发器、定时事件
  --add-drop-table      每条 CREATE TABLE 前带 DROP TABLE IF EXISTS，可重复导入

导入命令（Windows / Git Bash）
------------------------------------------------
# 步骤一：先建库（文件里没有 CREATE DATABASE）
mysql -uroot -p -h127.0.0.1 -P3306 \
  -e "CREATE DATABASE IF NOT EXISTS \`twelvet-fast\` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 步骤二：导入到该库 —— 一步到位，无需再执行任何增量脚本
mysql -uroot -p -h127.0.0.1 -P3306 --default-character-set=utf8mb4 twelvet-fast \
  < docs/db/twelvet-fast_2026-11-03.sql

# 方式二：命令行内直接 source（适合交互式）
#   mysql> CREATE DATABASE IF NOT EXISTS `twelvet-fast`;
#   mysql> USE `twelvet-fast`;
#   mysql> source F:/code/weiwei/docs/db/twelvet-fast_2026-11-03.sql

# 步骤三：验证
mysql -uroot -p -N -e "SELECT COUNT(*) FROM information_schema.tables
  WHERE table_schema='twelvet-fast';"        # 应为 120
mysql -uroot -p --default-character-set=utf8mb4 -N \

⚠️ 若终端里查询中文显示为乱码
------------------------------------------------
这是**终端编码问题，不是数据损坏**。Git Bash 默认按 GBK 显示，而 MySQL
客户端输出 UTF-8。实测字节 e7aea1 e79086 e59198 正是 UTF-8 的「管理员」。

验证方法（把输出重定向到文件后用 UTF-8 读取）：
  mysql -uroot -p --default-character-set=utf8mb4 -N \
    -e "SELECT username, nick_name FROM \`twelvet-fast\`.\`sys_user\` LIMIT 5;" > users.tsv
  py -3 -c "print(open('users.tsv', encoding='utf-8').read())"

日常查询建议在 MySQL Workbench / DBeaver / IDEA 数据库工具里进行，
或给 mysql 客户端加 --default-character-set=utf8mb4 并配合支持 UTF-8 的终端。
