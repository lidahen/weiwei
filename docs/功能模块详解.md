## 后端模块地图

后端为 Maven 多模块**单体**（13 个聚合模块 / 45 个 pom），由 `twelvet-admin` 聚合启动。

| 模块 | 职责 |
|---|---|
| `twelvet-admin` | **聚合启动入口**（8080），汇总全部模块单进程部署；持有全局配置（`ai.service.url`、`recommend.weights.*`、sa-token 等） |
| `twelvet-framework` | 框架层：统一返回体 / 分页 / 异常、租户上下文与拦截器、Redis 工具、操作审计 |
| `twelvet-system` | 系统域：用户 / 角色 / 菜单 / 租户 / 套餐（`sys_*` 表） |
| `twelvet-product` | **二手市场商品域**：商品、类目、收藏、关注、用户主页、**推荐系统服务端**、AI 导购代理 |
| `twelvet-trade` | **交易域**：订单、支付流水、物流、自提码、退款、议价、纠纷、评价、对账 |
| `twelvet-payment` | 支付渠道对接 |
| `twelvet-runner` | **社区互助域**：悬赏任务、接单流转、超时取消、自动确认 |
| `twelvet-exchange` | **交换广场域**：换物物品、交换意向、双边履约订单、面交码、评价、AI 初审、向量匹配、换物信用分 |
| `twelvet-im` | **即时通讯**：会话、消息、未读闭环、系统通知通道 |
| `twelvet-ai` | **AI 网关**：鉴权 / 配额 / 透传 ai-service；社区日报生成与推送 |
| `twelvet-quartz` | 定时任务调度（反射调用各模块 `bean.method`，如 `productRecommend.refreshInterestStat`） |
| `twelvet-dfs` / `twelvet-gen` | 文件服务 / 代码生成 |

## AI 服务与能力分层

FastAPI 单体，按路由划分能力域（`/ai/chat`、`/ai/assist/*`、`/ai/knowledge`、`/ai/rag-showcase/*`、`/ai/image`、`/ai/video`、`/recommend/*`、`/exchange-match/*` 等）。

浏览器侧调用方向为 **Java → Python 单向代理**：Python 不面向浏览器，也**不处理用户登录态**；业务读操作**直读同一个 MySQL 库**，用户身份与租户经 `X-User-Id` / `X-Tenant-Id` 请求头透传。

Agent 的写操作（如下单）经 Java 内部接口（`JAVA_BASE_URL` + `X-Internal-Token`）完成，**禁止直写业务表**；统一计费入 `ai_usage_daily` 账本。

- **主业区（持续迭代）**：导购 Agent（`/ai/chat`）、AI 初审（`/ai/moderation`）、AI 估价、识图填单、商品文案 / 配图（`/ai/assist/*`）、向量推荐（`/recommend/*`）。

## 前端

Umi Max 单应用：C 端（首页 / 商品 / 搜索 / 订单 / 社区 / IM / AI 助手）与管理后台（`/admin/marketplace/*`）同仓。认证走 Sa-Token（`Authorization: Bearer`），租户经 `X-Tenant-Code` 透传。

> ⚠️ 本仓库**不含 docker-compose.yml**（2026-10-21 删除）。本地依赖请直接安装原生 MySQL 8 + Redis，见 [ONBOARDING](ONBOARDING.md)；`backend/docker/` 是合并入仓时带进来的遗留编排，与当前三端结构不匹配，仅供查阅。

## 二手市场

**商品发布与管理**

- 审核流：`draft → auditing → onsale`（驳回带原因、可改再提），草稿暂存（`product_draft`）。
- 字段：多图、成色（全新~7 成以下）、一 / 二级类目（`product_category_dict`）、价格与原价、同城 / 位置（lat/lng 预留）、发货方式。
- 状态机：`draft / auditing / onsale / locked / sold / offshelf / rejected`；上下架、删除、置顶（`product_pin`）。
- 浏览计数（详情页埋点，**15 分钟窗口去重防刷**）；商品数量受租户套餐配额约束（超限 429）。

**搜索**

- MySQL **ngram 全文索引**（`ft_product_search`：title + description）替代 `LIKE '%q%'`，支持中文分词。
- 排序：综合（置顶 + 时间）、**相关度**（`MATCH...AGAINST` 打分）、价格升降、最多浏览。
- **热搜榜**：近 7 天租户内搜索词计数（仅记录登录用户 + 同词 5 分钟去重防刷）。
- **个人搜索历史**：去重、最近优先、可一键清空。

**收藏与降价提醒**

- 收藏写入**价格快照**（`product_favorite.original_price`），取消收藏对称回减 want_count。
- 每小时扫描对比快照与现价，降价则 **IM 推送收藏者**并刷新快照（幂等：同一轮降价只提醒一次，对审核改价 / 运营改价等任意路径通用）。

**交易全链路**

- 订单状态机：待付款 / 待发货 / 已发货 / 已完成 / 退款中 / 已关闭；商品与地址快照、超时关闭。
- 支付（`trade_pay` / `trade_pay_flow`）、物流（`trade_logistics`）、自提码、退款（`trade_refund`）、议价（`trade_bargain`）、纠纷、提现与对账。

**评价与卖家信用**

- 买卖互评（1-5 分 + 标签），管理员可隐藏 / 恢复。
- **卖家信用真实化**：主页好评率 / 完成订单数 / 评分由 `trade_review` / `trade_order` 实时聚合（不再硬编码）。
- 设计文档：[交易评价设计](交易评价设计.md)。

**关注**：`user_relation` 关注图；首页「关注」tab 为关注卖家的在售商品流。

## 社区动态

发帖 / 评论 / 点赞，帖子可关联商品卡片；热度分 `hot_score`（点赞 ×1 + 评论 ×3 口径，事件驱动重算），支持热榜排序。

## 社区互助

- 四类悬赏：代取快递 / 代买东西 / 代排队 / 其他。
- 流转：发布 → 接单 → 进行 → 待确认 → 完成；**超时未接单自动取消 + 退款**、**超时未确认自动确认**（Quartz）。
- 双向评价、状态流转 IM 通知。
- 支付解耦：互助任务可独立创建支付单，退款走 `pay_out_trade_no`。

## 交换广场

以物换物独立业务域（`twelvet-exchange`），与买卖交易解耦：换物物品没有售价，生命周期为 `auditing → onswap → locked → swapped / offshelf / rejected`。

- **发布与审核**：发布即 `auditing`；Quartz 每 10 分钟调用 `/ai/moderation/content`（`bizType=exchange_item`），low 自动上架、high 自动驳回 + IM 通知、medium 留人工。
- **交换意向（offer）**：从自己的 `onswap` 物品中选一件发起，可附留言与差价；同一物品同一人只允许一个 pending，72h 未处理自动过期。
- **接受意向（并发点）**：事务内乐观锁完成「意向占位 + 锁定双方物品」，其余 pending 自动婉拒，并生成交换订单与两个面交码。
- **双边履约**：面交时双方各自出示 6 位交换码，分别确认「已交付 / 已收到」；快递模式各自填运单号；双方确认后订单完成、物品 `swapped`、`swap_count+1`。
- **异常处理**：双方未交付时可取消；单方已交付只能走纠纷，后台 `force-complete` / `force-cancel`；`created` 超 7 天未双交付自动取消，待双方确认超 3 天自动完成。
- **评价与信用**：完成后 14 天内双向评价；`GET /exchange/credit/{userId}` 实时聚合完成率 / 违约 / 好评，信用分低于 40 拒绝发起意向。
- **智能匹配（二期）**：ai-service 按租户维护供给 / 需求两套 FAISS 索引（bge-m3），支撑广场「为你推荐」、详情页「可能想换 TA 的人」和每日 IM 匹配推送；embedding / 索引不可用时静默降级为空。
- **管理端**：`/admin/exchange/*` 物品审核、订单裁决、换物漏斗统计。
- **建表 / 菜单 / 任务**：依次执行 `backend/sql/exchange_schema.sql` → `exchange_menu.sql` → `exchange_match.sql`。
- 设计文档：[交换广场模块设计方案](交换广场模块设计方案.md) · [二期智能匹配与信用](交换广场二期-智能匹配与信用设计.md)。

## 即时通讯

用户会话 + **system 通知通道**：互助通知、社区日报、降价提醒、好物日报共用同一链路；未读数按消息位点服务端闭环。

## AI 能力

Java `twelvet-ai` 只做鉴权 / 租户 / 配额 / 转发，模型调用与 Agent 编排全部在 Python `ai-service`。

### AI 导购

`/product/ai-guide` → `/ai/chat`：LangGraph 多域 Agent（售前 / 售中 / 售后 / 社区四域子图 + 意图路由），工具直查 MySQL（商品检索 L0→L3 分级降级），下单等敏感操作走 **interrupt / confirm 两段式确认**，会话状态存 Redis checkpointer 支持多轮恢复；**自动注入用户兴趣画像上下文**（见「推荐与个性化系统」）。

### 知识库 RAG

文档切片 → bge-m3 向量化 → FAISS（按知识库持久化）→ 检索 + rerank；embedding 未配置时降级 SQL 全文匹配。

### 平台规则 RAG（RAG Showcase）

`/ai/rag-showcase/*` 提供规则问答、索引重建、语料与 trace：

- 12 篇**虚构演示**规则语料 / 57 个结构感知切片，按 `status / effective_date` 版本过滤。
- bge-m3 向量 + 自研中文 BM25 → RRF → bge-reranker 精排；答案强制 `[n]` 引用、无依据直接拒答。
- 68 条 golden set + B0–B3 四组 baseline；在线 / 离线评测报告见 [docs/rag-showcase](rag-showcase/README.md)。
- 已作为 L1 工具接入导购 Agent；embedding 不可用时可用离线 LSA 兜底复现评测。

### 内容生成

商品文案（LLM）、商品配图、图片生成、视频生成、TTS 语音。

### 社区日报与社区管家

- **社区日报**：每日 07:00 LLM 聚合平台数据生成（二手 / 动态 / 互助），IM 推送 + 页面存档，失败走模板兜底。见 [AI 社区日报设计](AI社区日报设计.md)。
- **社区管家**：互助悬赏搜索、社区概况、热帖搜索三个只读工具（租户强隔离）。

### AI 初审、识图与估价

- **AI 初审**：Quartz 每 10 分钟扫描待审商品 / 动态 → `/ai/moderation/content`（规则关键词 + LLM 结构化审查 + 可选 VISION 模型图片审查）→ low 自动通过 / high 自动驳回并 IM 通知作者 / medium 标注留人工；`ai.moderation.enabled` / `auto-action` 配置开关，AI 失败静默转人工，管理端审核列表带风险标注与筛选。
- **AI 识图填单 / AI 估价**（发布页）：多模态模型从实拍图识别类目 / 标题 / 描述 / 成色一键回填（仅填空字段）；估价 = 近 180 天真实成交分位数（p25 / p50 / p75）× 成色系数，**价格数字全部来自业务库统计，不使用 LLM 编价**。
- 设计文档：[AI 初审与发布助手设计](AI初审与发布助手设计.md) · [AI 内容生成设计](AI内容生成设计.md)。

### AI 音乐创作与模型管理

> 本节属**冻结区（HOBBY）**，仅演示，停止迭代。

- **AI 音乐创作**（`/ai/music/*`）：用户私有音色库 + 平台音色翻唱 + 文生歌 + AI 歌词助手。
  - **商汤 senseaudio** 覆盖：平台预置音色列表（`/v1/get_voice`）、文生歌 / 翻唱（`/v2/music/song/create`，Music 2.0 异步任务）、AI 写词 / 改写（`/v1/music/lyrics/{create,revise}`）、任务轮询（`/v1/music/song/pending/{task_id}`）。
  - **硅基流动 CosyVoice2 / IndexTTS-2** 覆盖：用户上传 10~60s 样本训练私有克隆音色（`/v1/uploads/audio/voice`）+ 用克隆音色合成 TTS（`/v1/audio/speech`，用于商品介绍语音 / 念白）。
  - 配额：文生歌 5 / 首 · AI 写词 1 / 次 · 克隆训练 3 / 天；强制实时录音 + 真人校验，合规授权签署后入库。
- **AI 模型管理 · 商汤 35 模型**（`ai_model` 表 + `/ai/model/types` 枚举）：35 个 senseaudio 模型已通过 `scripts/seed_senseaudio_models.py` 录入（TEXT×13 / VISION×2 / TTS×2 / ASR×5 / TRANSLATE×1 / ISOLATE×2 / MUSIC×2 / SFX×1 / AUDIO_GEN×1 / VIDEO×1 / IMAGE×4 / REALTIME×1），`vendor_router.get_vendor(db, model_type)` 按 default_flag 选默认模型，`SenseaudioUniversalVendor` 按 model_name 路由到对应端点；TTS / ASR / SFX / TRANSLATE / REALTIME 等未实现能力路由抛 `NotImplementedError` 占位。
- **创作工作台**：图片 / 视频 / 音乐 / 语音克隆 / TTS·ASR，见 [AI 创作工作台改造设计](AI创作工作台改造设计.md)。

### 统一配额

`ai_usage_daily` 租户 × 自然日单一账本，事前检查 + 事后计量，超额 / 套餐过期返回 429 友好文案。

## 管理后台

`/admin/marketplace/*`：运营仪表盘、商品审核（通过 / 驳回，**带 AI 初审风险标注与「仅看 AI 标疑」筛选**）、动态审核（同款 AI 标注）、评价管理（隐藏 / 恢复）、举报处理、用户管理、**推荐效果看板**（CTR，见下文）。

## 多租户与商业化

- 隔离：`TenantContext` + INSERT 字段拦截器 + XML 显式 `tenant_id` 过滤贯穿各 Mapper。
- 套餐（`sys_tenant`）：商品数量配额、AI 调用配额、过期自动拦截发布与 AI 调用。
- 用户隐私（`user_privacy`）：手机号搜索 / 陌生人私信 / 附近推荐开关（附近推荐开关已接入推荐流同城通道）。

## 推荐与个性化系统

> 详细设计：[二手市场首页推荐设计](二手市场首页推荐设计.md)。
> 原则：**向量 / 协同通道是增强而非依赖**，任何故障静默降级为规则通道；不上 ML 排序。

### 架构总览（首页推荐流）

```text
请求 GET /product/home/recommend（可选登录，未登录降级热门+新品）
  │
  ├─ 1. 用户画像 top3 类目（user_interest_stat）
  ├─ 2. 六路召回（LinkedHashMap 去重，记录首见通道）
  │     ① 兴趣类目 60   ② 热门 40   ③ 新品 30
  │     ④ 向量 20（Redis 缓存 10min）  ⑤ 看过又看 20（Redis 缓存 10min）  ⑥ 同城 15（隐私开关）
  ├─ 3. 过滤：本人商品 / 近3天已浏览 / 点过"不感兴趣"的商品
  ├─ 4. 打分（权重 application.yml 可配，A/B 分桶用户用 B 组权重）
  ├─ 5. 类目打散：同 cat_l1 单页最多 5 条（显式 catL1 过滤时跳过）
  ├─ 6. 推荐理由：你最近在看「…」/ 新上架 / 猜你喜欢 / 大家都在看 / 同城好物 / 本周热门
  └─ 7. 手工分页 + 曝光流水落库（scene + 位次 + A/B 组）
```

### 六路召回

| 通道 | 数据来源 | 召回量 | 理由文案 |
|---|---|---|---|
| 兴趣类目 | 用户画像 top3 类目 → 该类目在售商品（近 30 天） | 60 | 你最近在看「{类目名}」 |
| 热门 | `product.hot_score` DESC（趋势热度） | 40 | 本周热门 |
| 新品 | 近 7 天发布 | 30 | 新上架 |
| 向量 | seed = 近 30 天浏览商品向量均值 → FAISS top-N | 20 | 猜你喜欢 |
| 看过又看 | `product_view_log` 自连接共现（行为协同） | 20 | 大家都在看 |
| 同城 | 默认收货地址城市（受 `enable_nearby_recommend` 隐私开关控制） | 15 | 同城好物 |

### 用户兴趣画像（user_interest_stat）

- **行为权重**：浏览 ×1、收藏 ×3、下单 ×5；时间衰减 `exp(-ln2/14 × 天数)`（半衰期 14 天），窗口近 30 天。
- 粒度 `(user_id, cat_l1, cat_l2)`；**实时性**：浏览 / 收藏事件即时 upsert（30 分钟批量重建兜底修正）。
- **source 列**：`behavior`（批量重建清空重算）/ `init`（新用户兴趣引导种子，权重 5，重建保留）。
- 冷启动：登录用户首次访问弹兴趣引导弹窗选类目（可跳过，localStorage 标记）。

### 商品趋势热度（product.hot_score）

```text
hot_score = (近7日浏览数 + want_count×3 + chat_count×2) / POW(发布天数 + 2, 1.2)
```

用**近期浏览**而非累计浏览（gravity 衰减）——上周被翻牌的老物件能重新浮上来，新商品不被历史存量压制。每小时全量刷新。

### 向量召回（ai-service /recommend/*）

- 商品文本 = 标题 + 类目 + 描述截断 + 价格，bge-m3 向量化；**每租户一套 FAISS 索引**（IndexFlatIP + L2 归一 = cosine）。
- 增量同步：meta 记录 `update_time`，只重嵌新增 / 变更商品，下架自然剔除；每小时 Quartz 触发（无变更仅一次轻量 SELECT）。
- embedding 未配置 / 索引未构建 → code=503 → Java 侧摘除向量通道。

### 协同召回（看过又看）

`product_view_log` 自连接（共现用户数倒序）：首页以用户近 30 天浏览为 seed，详情页以当前商品为 seed。与向量（语义相似）互补的是行为协同。数据量增长后的终解：每日预聚合共现表。

### 负反馈

卡片 ✕「不感兴趣」→ `user_dislike_log`：该商品 30 天内不再推荐；同 `cat_l1` 每条扣 0.1 分（封顶 3 条 = −0.3，足以压过兴趣权重）。

### 曝光与 CTR 度量

- `recommend_impression_log`：scene（home_recommend / daily_push / detail_similar）、位次、A/B 组。
- 点击 = 曝光后 30 分钟内同用户浏览该商品（统计 SQL 关联 `product_view_log` 判定）。
- 看板：`/admin/marketplace/recommend-stats`（每日曝光 / UV / 点击 / CTR 按 A/B 组拆分 + 点击 Top10 商品，7 / 14 / 30 天切换）。

### A/B 实验

- `recommend.ab.*` 配置（twelvet-admin application.yml）：`enabled`（默认关）、`b-percent`（B 组流量比例）、`b.weights.*`（B 组五项实验权重）。
- 分桶 `userId % 100 < b-percent`，**稳定分组**（与设备 / 登录态无关）；曝光自动记录所属组，看板直接对比两组 CTR。

### 降级策略（全链路静默）

| 故障 | 行为 |
|---|---|
| 画像 / 热度任务失败 | 用旧画像 / 旧热度，退化为热门 + 新品双路 |
| ai-service 不可用 / embedding 未配置 | 摘除向量通道；详情页降级同类目热门 |
| Redis 不可用 | 召回缓存读写静默失败，直查 DB |
| 推荐接口整体异常 | 兜底回退"onsale 时间倒序" |
| 曝光 / 搜索词写入失败 | warn 日志，不影响主链路 |
