> 定位：首页「推荐」tab 从占位的时间倒序升级为**多路召回 + 规则打分**的个性化推荐流；二期补齐向量召回（详情页相似商品 + 首页向量通道）、曝光埋点与 CTR 统计、搜索关键词埋点。

## 0. 个性化增强七件套（第三轮实现）

| # | 能力 | 实现要点 |
|---|---|---|
| 1 | 收藏降价提醒 | 每小时 Quartz `productRecommend.scanPriceDrop`：先给无快照的存量收藏播种基线价（不通知），再对比 `product_favorite.original_price` 快照与现价，降价则 IM 推送收藏者并刷新快照（幂等，同一轮降价只提醒一次）；发布时收藏写入快照。跨改价路径通用（审核通过改价/运营改价均覆盖），无需挂审核链路 |
| 2 | AI 导购个性化 | `AiGuideController.injectLoginUser` 注入 `interestHint`（top3 兴趣类目 + 近 14 天浏览商品标题/价格），Python `/ai/chat` 前置为 SystemMessage（`runner._to_lc_messages` 保留 role=system）；无画像不注入 |
| 3 | 搜索历史 + 热搜榜 | `GET /product/search/history`（个人去重，最近优先）、`DELETE /product/search/history`、`GET /product/search/hot`（近 7 天租户内计数倒序，≥2 字符）；搜索页热搜 chips（前 3 名高亮）+ 历史 chips + 清空 |
| 4 | 实时兴趣更新 | 浏览（detail 埋点，权重 1）与收藏（addFavorite，权重 3）事件即时 `bumpInterestByProduct` upsert 画像行，推荐随浏览即时变化；30 分钟批量重建兜底修正（下单信号仍靠批量） |
| 5 | 新用户兴趣冷启动 | `user_interest_stat.source`（behavior/init）：`POST /product/interest/init` 写类目种子行（weight=5, source='init'），批量重建只清 behavior 行，种子长期生效；首页对"登录 + 本机未引导"用户弹 `InterestGuideModal` 选类目（localStorage 标记，可跳过） |
| 6 | "看过又看"协同召回 | `view_log` 自连接（共现用户数倒序）→ 第六路召回 `selectAlsoViewed`，reason"大家都在看"；行为协同与向量（语义相似）互补；失败静默跳过 |
| 7 | 负反馈"不感兴趣" | `user_dislike_log` 流水；`POST /product/interest/dislike` 记录（30 天窗口）；推荐流排除该商品 + 同 cat_l1 每条扣 0.1 分（封顶 3 条 = -0.3）；ProductCard 推荐 tab 卡片右上角 ✕ 按钮，点击本地移除 |

首页推荐流现为**六路召回**：兴趣类目 → 热门 → 新品 → 向量（猜你喜欢）→ "看过又看"协同（大家都在看）→（负反馈过滤/降权贯穿打分）。

## 1. 目标与非目标

**目标**

- 首页 `recommend` tab 个性化：登录用户按「兴趣类目 + 热门 + 新品 + 向量」四路召回统一打分排序；匿名/无行为用户自动降级为热门 + 新品
- 每条商品带推荐理由 `reason`（"你最近在看「数码」" / "新上架" / "猜你喜欢" / "本周热门"），前端卡片角标展示
- 详情页「相似推荐」区块：向量召回（bge-m3 + FAISS），不可用时降级同类目热门
- 数据侧配套：`user_interest_stat` 兴趣画像表 + `product.hot_score` 热度分 + `recommend_impression_log` 曝光流水 + `search_keyword_log` 搜索词流水，Quartz 定时刷新/同步
- 管理端 CTR 统计接口（复用 `admin:marketplace:*` 权限）
- 顺手修复两个占位：`nearby` tab 改热度排序；`follow` tab 接真实关注关系（替换硬编码 seller_demo 102）

**非目标（本期不做）**

- 不做 lat/lng 距离排序（需发布端定位采集 + 用户授权 UX 的产品决策，DDL 字段已预留）
- 不做协同过滤 / ML 排序（单社区数据量撑不起共现矩阵，架构上召回通道可插拔，数据厚了再加）
- 不做 A/B 框架（权重为代码常量，先跑通）
- 搜索词暂只埋点不入画像（浏览行为已隐式捕捉搜索后兴趣，词→类目映射待热搜榜需求一起做）

## 2. 召回通道与打分

### 召回通道（四路，候选去重合并）

| 通道 | 数据来源 | 召回量 | 理由文案 |
|---|---|---|---|
| 兴趣类目 | `user_interest_stat` 用户 top3 类目 → 该类目 onsale 商品（近 30 天） | 60 | 你最近在看「{类目名}」 |
| 热门 | `product.hot_score` DESC | 40 | 本周热门 |
| 新品 | `publish_time` 近 7 天 DESC | 30 | 新上架 |
| 向量（二期） | seed=近 30 天浏览商品向量均值 → ai-service FAISS top-N | 20 | 猜你喜欢 |

向量通道仅做召回扩充，**不参与打分**（向量命中商品按其自身 hot/recency 参与排序），待 CTR 数据验证后再融入权重。

### 打分公式（候选集小，Java 内存排序）

```
score = 0.5 × interest + 0.3 × hotNorm + 0.2 × recency
```

- `interest`：商品 cat_l1 命中用户 top3 类目时 = 该类目权重 / 最大类目权重（0~1），未命中 = 0
- `hotNorm`：`hot_score / 候选集最大 hot_score`（0~1）
- `recency`：`exp(-发布距今天数 / 14)`（半衰期两周）
- 同分按 `publish_time` 倒序兜底

### 过滤与业务规则

- 只取 `onsale`；租户隔离（JOIN product 显式过滤，行为表无 tenant_id 列）
- 剔除本人商品；剔除登录用户近 3 天已浏览过的商品（`product_view_log`）
- 类目打散：同一页内同 `cat_l1` 最多 5 条（防信息茧房）
- 支持 `catL1` 参数过滤（兼容现有前端签名）

### 冷启动与降级

| 场景 | 行为 |
|---|---|
| 未登录 | 无兴趣通道，热门 + 新品双路 |
| 登录但画像为空（新用户/无行为） | 同未登录 |
| 兴趣类目下无在售商品 | 该通道自然为空，不强行凑数 |
| 召回合计 < pageSize | 如实返回，前端已有 Empty 态 |

## 3. 聚合口径与调度

**兴趣画像（每 30 分钟，全量重建）**

- 行为权重：浏览 ×1（`product_view_log.view_time`）、收藏 ×3（`product_favorite.fav_time`，取消收藏即删行天然有效）、下单 ×5（`trade_order.buyer_id`，`status != 'closed'`，按 `create_time`）
- 勘误（2026-09-06）：`product_view_log` 此前**全链路无写入**（日报/画像/CTR 都在读但没人写）——已在 `/product/detail` 补上埋点（`view_count+1` + 登录用户写流水，见 `IRecommendService.recordView`），否则画像只剩收藏/下单两个信号、向量 seed 与 CTR 恒为空
- 时间窗口：近 30 天；时间衰减：`exp(-ln2/14 × 天数)`（半衰期 14 天），SQL `EXP/LN/TIMESTAMPDIFF` 原生计算
- 粒度：`(user_id, cat_l1, cat_l2)`，`cat_l2` 空存 `''`；查询时按 `cat_l1` 汇总取 top
- 重建 = 先 `DELETE` 全表，再三段 `INSERT ... SELECT ... GROUP BY`（GROUP BY 首列 `tenant_id` 天然覆盖全部租户，无需枚举；收藏/下单段 `ON DUPLICATE KEY UPDATE weight = weight + VALUES(weight)` 累加）。行为表无 tenant_id 列，租户隔离依赖 JOIN product 显式过滤（`product.tenant_id IS NOT NULL` 兜底）

**商品热度（每小时，全量刷新，gravity 衰减）**

```sql
hot_score = (view_count + want_count*3 + chat_count*2)
            / POW(TIMESTAMPDIFF(HOUR, COALESCE(publish_time, create_time, NOW()))/24 + 2, 1.2)
```

**调度**：复用 twelvet-quartz 反射模式（同 `runnerTask` / `aiDailyReport`），Bean `@Component("productRecommend")`：

| invoke_target | cron | 说明 |
|---|---|---|
| `productRecommend.refreshInterestStat` | `0 */30 * * * ?` | 全量重建兴趣画像（GROUP BY tenant_id 覆盖全部租户；只清 behavior 行，init 种子保留） |
| `productRecommend.refreshHotScore` | `0 0 * * * ?` | 全量刷新商品热度分 |
| `productRecommend.scanPriceDrop` | `0 20 * * * ?` | 收藏降价扫描：播种缺失基线 → 对比快照与现价 → IM 通知 + 刷新快照（幂等） |
| `productRecommend.syncVectors` | `0 40 * * * ?` | 每小时增量同步商品向量索引（原每日，提速新品进向量召回） |
| `productRecommend.purgeExpiredLogs` | `0 50 3 * * ?` | 清理 90 天前的浏览/曝光/搜索词/负反馈流水 |
| `productRecommend.refreshDailyStats` | `0 0 5 * * ?` | 昨日浏览明细聚合进 product_stats_daily（幂等覆盖） |
| `productRecommend.pushDailyPicks` | `0 30 7 * * ?` | 好物日报：有画像用户按兴趣推 3 件好物 |

**向量索引（ai-service 侧，`app/services/product_vector.py`）**

- 每租户一套：`data/faiss_indexes/product_t{tid}.faiss + .meta.json + .npy`（IndexFlatIP + L2 归一化 = cosine；meta 记 product_id 与 update_time 映射，npy 存向量矩阵，重建无需重嵌）
- 商品文本 = 标题 + 类目 + 描述截断 200 字 + 价格；增量：只重嵌新增/变更商品，下架/删除自然剔除
- 复用 `embedding_service`（bge-m3）；FAISS 同步调用统一 `asyncio.to_thread`（同 rag_service 惯例）

## 4. 表设计

```sql
-- 用户兴趣画像（定时任务全量重建，可随时 DROP 重建）
CREATE TABLE IF NOT EXISTS `user_interest_stat` (
  `id`          BIGINT        NOT NULL AUTO_INCREMENT,
  `tenant_id`   BIGINT        NOT NULL COMMENT '租户ID',
  `user_id`     BIGINT        NOT NULL COMMENT '用户ID',
  `cat_l1`      VARCHAR(20)   NOT NULL COMMENT '一级类目',
  `cat_l2`      VARCHAR(20)   NOT NULL DEFAULT '' COMMENT '二级类目(空串=仅一级)',
  `weight`      DECIMAL(12,4) NOT NULL DEFAULT 0 COMMENT '兴趣权重(浏览1/收藏3/下单5,含时间衰减)',
  `update_time` DATETIME      NULL DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_cat` (`user_id`, `cat_l1`, `cat_l2`),
  INDEX `idx_tenant_user` (`tenant_id`, `user_id`, `weight`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户兴趣画像(首页推荐召回)';

-- 商品热度分（gravity 时间衰减，Quartz 每小时刷新）
ALTER TABLE `product`
  ADD COLUMN `hot_score` DECIMAL(12,4) NOT NULL DEFAULT 0 COMMENT '热度分(view+want*3+chat*2)/gravity衰减' AFTER `chat_count`,
  ADD INDEX `idx_hot_score` (`hot_score`);

-- 推荐曝光流水（点击 = 曝光后 30 分钟内同用户浏览该商品，由统计 SQL 关联 view_log 判定）
CREATE TABLE IF NOT EXISTS `recommend_impression_log` (
  `id`          BIGINT      NOT NULL AUTO_INCREMENT,
  `tenant_id`   BIGINT      NULL DEFAULT NULL COMMENT '租户ID(单租户模式可空)',
  `user_id`     BIGINT      NULL DEFAULT NULL COMMENT '用户ID(匿名曝光为空)',
  `product_id`  BIGINT      NOT NULL,
  `scene`       VARCHAR(30) NOT NULL DEFAULT 'home_recommend' COMMENT '曝光场景(home_recommend/detail_similar)',
  `position`    INT         NOT NULL DEFAULT 0 COMMENT '曝光位次(从1起)',
  `create_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_time` (`create_time`),
  INDEX `idx_user_time` (`user_id`, `create_time`),
  INDEX `idx_product_time` (`product_id`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='推荐曝光流水(CTR统计)';

-- 搜索关键词流水（热搜榜/搜索历史/关键词兴趣的后续数据源，本期只埋点）
CREATE TABLE IF NOT EXISTS `search_keyword_log` (
  `id`          BIGINT      NOT NULL AUTO_INCREMENT,
  `tenant_id`   BIGINT      NULL DEFAULT NULL,
  `user_id`     BIGINT      NULL DEFAULT NULL,
  `keyword`     VARCHAR(60) NOT NULL,
  `create_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_time` (`create_time`),
  INDEX `idx_user_time` (`user_id`, `create_time`),
  INDEX `idx_keyword` (`keyword`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='搜索关键词流水';
```

DDL 落 `backend/data/product-recommend-init.sql`（含 sys_job 注册与回滚语句），并在库执行。

## 7. 降级策略

| 故障 | 行为 |
|---|---|
| 画像任务失败/漏跑 | `user_interest_stat` 为旧数据或空 → 退化为热门 + 新品双路，首页可用 |
| 热度任务失败 | `hot_score` 为旧值 → 排序略陈旧，不影响可用性 |
| ai-service 不可用 / embedding 未配置 / 索引未构建 | 首页摘除向量通道（规则通道独立成链）；详情页降级同类目热门；每日同步任务失败仅记日志 |
| 首页接口异常 | 兜底走原 `selectProductList("onsale", ...)` 时间倒序（try/catch 包裹） |
| 曝光/搜索词写入失败 | 静默（warn 日志），绝不影响推荐主链路 |

## 11. 风险与遗留

- 行为表（`product_view_log`/`product_favorite`）无 `tenant_id` 列，隔离依赖 JOIN product 显式过滤；若后续加租户列可简化
- `trade_order` 聚合跨模块直查（沿用 UserMapper 查 trade_review 的先例），模块拆分时需收敛
- 全量重建画像在用户量上万后需改增量；当前量级（<百用户）无压力（浏览/收藏已有实时 bump 兜底感知）
- 向量通道与"看过又看"通道当前仅做召回不参与打分（公式保持稳定），待曝光/CTR 数据积累后再决定是否融入权重
- 向量索引同步依赖每日 Quartz + ai-service 在线；商品发布后最长 1 天才入索引（可后续在审核通过链路补一次单商品 upsert）
- 降价提醒通过每小时快照扫描实现（幂等），最高 1 小时延迟；如需实时可在审核通过链路补即时触发
- **lat/lng 距离排序暂缓**：需要发布表单定位采集 + 用户授权交互的产品决策，DDL 字段已预留，后端 ready 后仅差一个 Haversine 排序分支
- 待办清单：负反馈词级粒度（当前类目粒度）、协同共现预聚合表（数据量增长后切换）、搜索点击归因（详情页带搜索来源）
