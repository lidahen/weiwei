# 交易评价设计

> **2026-10-27 注**：本文引用的 2026-10-21 之前 SQL 初始化脚本已于 2026-10-27 清理；
> 相关表结构已并入 [docs/db 全量基线](db/twelvet-fast_2026-10-21.sql)，新环境按 README 基线导入。

> 对应实现：`twelvet-trade` 模块（`TradeReview*`）+ `ui/src/pages/marketplace`（Review / OrderDetail / ProductDetail / admin/ReviewManage）。
> 初始化脚本：`backend/data/trade-review-init.sql`、`backend/data/trade-review-menus.sql`。

## 1. 目标与范围

买家收货确认（订单 `done`）后，买卖双方可互评：1-5 星 + 文字 + 图片 + 标签，可匿名。提交即公开（不先审后显），运营后台可隐藏/恢复。

不做：追评（`supplement` 列保留未用）、IM 通知、超时自动好评、评分参与搜索排序。

## 2. 表结构

复用既有 `trade_review` 表（role 双向设计），本轮补齐：

| 变更 | 说明 |
| --- | --- |
| `tenant_id BIGINT NOT NULL DEFAULT 1` | 租户隔离，随全站约定 |
| `product_id BIGINT NULL` | 冗余自订单，商品页评价列表免 join |
| `status varchar(20) DEFAULT 'normal'` | `normal` / `hidden`（运营隐藏，软删） |
| `UNIQUE KEY uk_order_role(tenant_id, order_id, role)` | 一单一方向一评，防重 + 并发兜底 |
| `INDEX idx_reviewee_tenant(tenant_id, reviewee_id)` | 卖家/买家主页聚合查询 |

评分挂在订单上：写入前置条件是真实完成交易，天然防刷。卖家的信用 = `role='buyer'`（买家给卖家）评价的聚合；买家侧同理。聚合实时 AVG 计算，不加冗余信用表（同跑腿模块先例）。

## 3. 写入规则（`TradeReviewServiceImpl.submit`）

1. 订单存在且 `status == 'done'`（仅确认收货后可评）；
2. 按 `userId` 与订单 `buyerId`/`sellerId` 匹配确定 `role`，不信任前端传值，两者都不是则拒绝；
3. `rating` 1–5、`content` ≤ 500 字、`images` JSON 数组 ≤ 9 张、`tags` JSON 数组 ≤ 5 个；
4. 一单一方向一评：先查重，`uk_order_role` 的 `DuplicateKeyException` 兜底并发；
5. 匿名（`anonymous=1`）：公开查询中昵称/头像在 SQL 层替换为「匿名用户」/NULL。

## 4. 接口

### C 端（`TradeReviewController`，/trade/review，Sa-Token 登录态）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/trade/review` | body: orderId/rating/content/images(JSON串)/tags(JSON串)/anonymous |
| GET | `/trade/review/order/{orderId}` | 该订单双向评价 + 本人角色/是否已评 |
| GET | `/trade/review/product/{productId}` | 商品页评价（role='buyer'、status='normal'，分页 + 均分汇总） |
| GET | `/trade/review/user/{userId}` | 某用户作为卖家收到的评价（分页 + 汇总） |

### 运营后台（`AdminMarketplaceController`，@SaCheckPermission("admin:marketplace:*")）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/marketplace/review/page` | status/role/keyword 筛选，平台视角（不过滤租户，同 Feed 审核惯例） |
| POST | `/admin/marketplace/review/hide` | 隐藏（status='hidden'） |
| POST | `/admin/marketplace/review/show` | 恢复（status='normal'） |

### 卖家主页打通（twelvet-product `UserProfileServiceImpl`）

写死的 `goodReviewRate=98`、`completedOrders=27` 改为真实聚合（好评率 = 卖家收到的 4-5 星占比；无评价返回 null，前端沿用 `|| 100` 兜底）。跨表 SQL 放在 product 模块 `UserMapper.xml`（先例：DailyReportMapper.xml 跨模块查表），避免 trade→product 的依赖环反向传染。

## 5. 前端

- `Review.tsx`（原占位页转正）：按服务端返回的 `myRole` 渲染买家/卖家侧表单（标签预设不同），已评则展示结果态；
- `OrderDetail.tsx`：`done` 后展示「评价」Card（双方评价），未评一侧显示「去评价/评价买家」；
- `ProductDetail.tsx`：新增「用户评价」Card（均分 + 最新若干条，带图预览）；
- `admin/ReviewManage.tsx`：评价管理表格（筛选/隐藏/恢复），路由 `/admin/marketplace/review`。

## 6. 手工验证清单

1. 执行 `trade-review-init.sql` 与 `trade-review-menus.sql`；
2. 未完成订单（unpaid/shipped）提交评价 → 报「仅确认收货后可评价」；
3. 确认收货后买家提交 → 成功；重复提交 → 报「已评价过」；
4. 卖家侧提交评价 → 成功，`GET /trade/review/order/{id}` 双向可见；
5. 商品详情页出现「用户评价」；卖家主页好评率/完成订单数不再是写死的 98/27；
6. 后台隐藏某条评价后，商品页列表不再展示，恢复后重新可见；
7. 非订单双方用户提交 → 拒绝；匿名评价在列表中昵称显示「匿名用户」。
