# Weiwei 单机 2C2G 部署方案（零额外成本）

> 适用场景：自营打样阶段，1 个小区试点，< 100 在线 / 30 并发。
> 成本：仅云服务器基础费用，无额外流量费/数据库费。
> OSS：阿里云 OSS 已独立开通，文件存储走那里。
> 不适用：需要 7×24 SLA 的对外业务（单点故障即全站不可用）。

## 1. 内存预算（2G 机器的极限）

| 组件 | 估算 |
|---|---|
| OS + Docker daemon | 250m |
| Java 后端 `-Xmx384m` | 650m |
| MySQL 8（buffer pool 128m） | 350m |
| Redis 7-alpine | 60m |
| ai-service（uvicorn 单 worker） | 250m |
| Nginx + UI | 50m |
| **合计** | **~1.6G / 2G** |

**关键点**：JVM 从之前的 `-Xmx768m` 降到 `-Xmx384m`，MySQL buffer pool 从 384m 降到 128m，才能塞下。

**强制加 2G swap**（机器最便宜的保险）：
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

> swap 不是银弹，只是避免突发 OOM。MySQL 和 Redis 频繁 swap 会拖慢响应，所以 buffer pool 和 maxmemory 必须设小。

## 2. 容器化方案

### 2.1 `docker-compose.yml`（单文件，全部在一台）

```yaml
version: '3.9'

services:
  nginx:
    image: nginx:1.27-alpine
    restart: on-failure:5
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./ui/dist:/usr/share/nginx/html:ro
      - ./nginx/ssl:/etc/nginx/ssl:ro
    depends_on: [backend]
    deploy:
      resources:
        limits:
          memory: 80m

  backend:
    build: ./backend
    restart: on-failure:5
    environment:
      - TZ=Asia/Shanghai
      - SPRING_PROFILES_ACTIVE=pro
      - AI_SERVICE_URL=http://ai-service:8001
      - JASYPT_PASSWORD=${JASYPT_PASSWORD}
    env_file: ./backend/.env
    expose: ["8080"]
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    deploy:
      resources:
        limits:
          memory: 900m

  mysql:
    image: mysql:8.0.32
    restart: on-failure:5
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: twelvet-fast
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-buffer-pool-size=128M
      - --innodb-log-file-size=64M
      - --innodb-flush-log-at-trx-commit=2
      - --innodb-flush-method=O_DIRECT
      - --max-connections=30
      - --thread-cache-size=4
      - --table-open-cache=100
      - --bind-address=127.0.0.1
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    expose: ["3306"]
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-uroot", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 15s
      timeout: 5s
      retries: 5
    deploy:
      resources:
        limits:
          memory: 500m

  redis:
    image: redis:7-alpine
    restart: on-failure:5
    command: ["redis-server", "--maxmemory", "96m", "--maxmemory-policy", "allkeys-lru"]
    volumes:
      - ./data/redis:/data
    expose: ["6379"]
    deploy:
      resources:
        limits:
          memory: 150m

  ai-service:
    build: ./ai-service
    restart: on-failure:5
    env_file: ./ai-service/.env
    environment:
      - DATABASE_URL=mysql+aiomysql://root:***@mysql:3306/twelvet-fast
      - REDIS_URL=redis://redis:6379/0
      - TZ=Asia/Shanghai
    expose: ["8001"]
    depends_on:
      mysql:
        condition: service_healthy
    deploy:
      resources:
        limits:
          memory: 400m
```

> ⚠️ MySQL `bind-address: 127.0.0.1`（关键，不暴露到公网）
> ⚠️ Redis 用 `redis:7-alpine` 而非 `redis-stack`：省 100–150m，但 **ai-service 的 langgraph-checkpoint-redis 需要 RediSearch FT 索引**。
>
> **二选一**：
> - **方案 A（推荐，省内存）**：把 ai-service 里的 checkpointer 改成 `SqliteSaver` 或 `MemorySaver`，redis 用普通版。代价：服务重启后 AI 对话历史丢失（可接受，因为打样阶段数据少）。
> - **方案 B**：保留 `redis-stack-server`，内存预算 1.7G，留 300m 余量，紧但能跑。

### 2.3 `nginx/nginx.conf`

```nginx
worker_processes 1;
worker_rlimit_nofile 4096;

events { worker_connections 1024; }

http {
  include       /etc/nginx/mime.types;
  sendfile      on;
  tcp_nopush    on;
  keepalive_timeout 65;
  client_max_body_size 25m;
  gzip on;
  gzip_types text/plain text/css application/json application/javascript image/svg+xml;

  upstream backend { server backend:8080; keepalive 32; }

  server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
  }

  server {
    listen 443 ssl;
    http2 on;
    server_name ershou.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    root  /usr/share/nginx/html;
    index index.html;

    location / {
      try_files $uri $uri/ /index.html;
      add_header Cache-Control "public, max-age=600";
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|webp|svg|woff2?)$ {
      expires 30d;
      add_header Cache-Control "public, immutable";
    }

    location /api/ {
      proxy_pass http://backend/;
      proxy_http_version 1.1;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
      proxy_read_timeout 120s;
      proxy_connect_timeout 10s;
    }

    location /im/ {
      proxy_pass http://backend/im/;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      proxy_read_timeout 3600s;
    }
  }
}
```

## 5. 备份方案（走阿里云 OSS）

### 5.1 备份脚本

`/opt/weiwei/scripts/backup.sh`：
```bash
#!/usr/bin/env bash
set -euo pipefail
TS=$(date +%Y%m%d-%H%M%S)
OUT=/opt/weiwei/backup/db_${TS}.sql.gz

# 用 docker exec 进容器跑 mysqldump
docker exec weiwei-mysql-1 sh -c "mysqldump -uroot -p'${MYSQL_ROOT_PASSWORD}' \
  --all-databases --single-transaction --routines --triggers --skip-comments --quick" \
  | gzip > "$OUT"

SIZE=$(du -h "$OUT" | cut -f1)
echo "$(date '+%F %T') backup done: $SIZE"

# 上传到阿里云 OSS（已有 ossutil）
ossutil64 cp "$OUT" oss://image123qwe/weiwei-backup/db/ --meta Content-Type:application/gzip

# 本地只保留 3 天
find /opt/weiwei/backup -name 'db_*.sql.gz' -mtime +3 -delete

# OSS 端 30 天过期（用 ossutil lifecycle）
echo "$(date '+%F %T') cleanup done"
```

> 你项目里 `application.yml` 已经有阿里云 OSS 的 accessKey/secretKey，备份脚本可以直接复用同一套密钥。

### 5.2 安装 ossutil

```bash
curl -O https://gosspublic.alicdn.com/ossutil/1.7.18/ossutil64
chmod 755 ossutil64
sudo mv ossutil64 /usr/local/bin/

# 配置密钥（用已有的 OSS accessKey）
# ⚠️ 2026-09-23：站点已整体迁到新账号 your-account-id / bucket your-bucket，
#    密钥同步更新。旧账号 your-old-account-id 即将到期，勿再使用。
ossutil64 config -e oss-cn-beijing.aliyuncs.com \
  -i your-access-key-id \
  -k your-access-key-secret
```

### 5.3 cron

```cron
# 每天凌晨 3 点备份
0 3 * * * /opt/weiwei/scripts/backup.sh >> /opt/weiwei/scripts/backup.log 2>&1
```

### 5.4 OSS 生命周期（控制台配置）

OSS bucket → 设置 → 生命周期规则：
- 路径：`weiwei-backup/db/`
- 策略：30 天后过期删除

## 7. 常见踩坑

| 问题 | 原因 | 解决 |
|---|---|---|
| 容器 OOM Kill | 2G 不够，没设 memory limits | compose 每个服务设 `limits.memory` |
| MySQL 启动慢 | buffer pool 太小 + 大量 SQL 初始化 | init.sql 跑一次后改空，避免每次重建 |
| AI 服务卡死 | faiss 索引过大 + 多 worker | 单 worker，FAISS 索引设 `index_limit` |
| 后端频繁重启 | JVM 堆不够，频繁 Full GC | 看 GC log，调到 `-Xmx448m` 上限 |
| swap 频繁使用 | 内存预算超了 | 砍 MySQL buffer pool 或 JVM 堆 |
| 备份卡住 | mysqldump 大表锁表 | 加 `--single-transaction` + `--quick` |
| OSS 上传失败 | 密钥权限不够 | 确认 accessKey 有 `oss:PutObject` 权限 |
| HTTPS 证书过期 | 自动续期没配 | certbot 或 cloud.tencent.com 免费证书 90 天续 |

## 8. 容量边界（重要）

**这个配置能撑多大？**

| 指标 | 上限 |
|---|---|
| 注册用户数 | 5,000–10,000 |
| 日活 | 200–500 |
| 并发请求 | 30–50 |
| AI 图片生成 | 50–100 张/天 |
| IM 长连 | 50–100 |
| 数据库表数 | 80+（当前 84 张够） |
| 单商品图片 | < 5 张 |

**超过这个边界**：
- 在线 > 500 → 升 4G
- AI 图片 > 200 张/天 → 把 ai-service 迁到独立小机器（4C4G 轻量）
- 数据库 > 5GB → 迁腾讯云 TDSQL-C（按量付费，约 ¥0.5/GB/月）

## 11. 一句话总结

**单机 2C2G 能跑 Weiwei**，核心 5 步：
1. **JVM 降到 `-Xmx384m`**，MySQL buffer pool 降到 128m
2. **MySQL / Redis / AI 都不暴露公网**（用 `expose` 而非 `ports`）
3. **Nginx 反向代理所有入口**，加 HTTPS
4. **2G swap + 服务级 memory limits** 兜底
5. **cron 每日备份到阿里云 OSS**（复用现有 OSS 密钥）

这个配置够撑「自营打样」阶段。真上线后按升级路径走，单点变双点。
