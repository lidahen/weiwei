# 服务拆分重构方案

> 版本：v1.0
> 日期：2026-08-20
> 范围：从 `twelvet-trade` 中抽出支付服务 + 新建跑腿服务

---

## 一、重构背景与目标

### 1.1 现状问题

`twelvet-trade` 模块当前混合了三类职责：

| 类别 | 具体代码 | 职责定位 |
|------|----------|---------|
| 通用支付 | `PayOrder`、`PayOrderService`、`PaymentGateway`、`AlipayGateway`、`WechatGateway`、`PaymentNotifyController` | 通用基础设施 |
| 商品交易 | `TradeOrder`、`TradeOrderController/ServiceImpl`、`TradePayController`、`TradeLogisticsMapper`、`AdminMarketplace*`、`CsDispute*` | 交易业务域 |
| 租户续费 | `TenantRenewOrder`、`TenantRenewPayController/Service`、`TenantRenewOrderMapper` | 平台运维收款 |

**问题**：
- 支付作为通用能力，被塞在具体业务模块里，其他业务无法复用
- 未来接入更多支付渠道时，改动范围扩散到 trade 内部
- 新增跑腿业务无法干净复用支付能力

### 1.2 重构目标

1. **单一职责**：支付独立成服务，交易域纯化
2. **可复用**：其他业务模块直接注入支付 API，不感知支付细节
3. **风险隔离**：支付故障不影响交易模块
4. **低改动成本**：迁移代码量大，但对外接口稳定

## 二、拆分方案总览

### 2.1 目标结构

```
backend/
├── twelvet-payment/            ← 【新建】支付服务
│   ├── twelvet-payment-api/
│   └── twelvet-payment-server/
├── twelvet-trade/              ← 【瘦身】只保留商品交易
│   ├── twelvet-trade-api/
│   └── twelvet-trade-server/
├── twelvet-runner/             ← 【新建】跑腿服务
│   ├── twelvet-runner-api/
│   └── twelvet-runner-server/
└── ...（其他模块不动）
```

### 2.2 服务边界（决策记录）

| 服务 | 包含 | 不包含 |
|------|------|--------|
| `twelvet-payment` | PayOrder 实体、支付网关（支付宝/微信）、支付回调、租户续费支付 | 订单流转、物流、纠纷 |
| `twelvet-trade` | TradeOrder、TradePay、AdminMarketplace、CsDispute | 支付网关实现、租户续费 |
| `twelvet-runner` | 跑腿任务、接单、资金流转调用 payment API | 支付网关实现 |

### 2.3 为什么这么切（决策理由）

1. **支付 = 基础设施**：通用能力独立，多业务复用（trade 下单、runner 收款、租户续费都是它）
2. **租户续费归支付**：续费是"平台收款"，本质就是创建 PayOrder + 支付，跟 C2C 交易性质不同
3. **trade 保留交易闭环**：订单 + 支付适配 + 物流 + 纠纷是一个业务闭环，拆开反而别扭
4. **runner 独立新建**：跑腿是完全新的业务域，独立清晰

## 三、服务详细设计

### 3.1 `twelvet-payment`（支付服务）

#### 模块结构

```
twelvet-payment/
├── pom.xml
├── twelvet-payment-api/
│   ├── pom.xml
│   └── src/main/java/com/twelvet/payment/api/
│       ├── domain/
│       │   └── PayOrder.java                # 支付单实体（跨模块共享）
│       ├── enums/
│       │   ├── PayChannel.java              # 支付渠道枚举
│       │   └── PayStatus.java               # 支付状态枚举
│       ├── dto/
│       │   ├── PayRequestDTO.java           # 支付请求
│       │   ├── PayCallbackDTO.java          # 支付回调
│       │   └── PaySettleDTO.java            # 资金结算请求
│       └── service/
│           ├── IPayOrderService.java        # 支付单服务接口
│           ├── IPaymentGateway.java         # 支付网关接口
│           ├── IAlipayGateway.java
│           ├── IWechatGateway.java
│           └── ITenantRenewPayService.java
└── twelvet-payment-server/
    ├── pom.xml
    └── src/main/java/com/twelvet/payment/server/
        ├── controller/
        │   ├── PaymentNotifyController.java      # 支付平台回调
        │   └── TenantRenewPayController.java     # 租户续费支付
        ├── service/
        │   ├── impl/
        │   │   ├── PayOrderServiceImpl.java
        │   │   ├── AlipayGatewayImpl.java
        │   │   ├── WechatGatewayImpl.java
        │   │   └── TenantRenewPayServiceImpl.java
        ├── mapper/
        │   ├── PayOrderMapper.java
        │   └── TenantRenewOrderMapper.java
        └── domain/
            └── TenantRenewOrder.java         # 续费订单实体
```

#### API 接口

```java
/** 支付单服务对外接口 */
public interface IPayOrderService {

    /** 创建支付单（返回支付参数） */
    PayOrder createPayOrder(PayRequestDTO request);

    /** 支付回调处理 */
    boolean handleCallback(PayCallbackDTO callback);

    /** 资金结算（订单完成后释放资金到目标账户） */
    boolean settle(PaySettleDTO settle);

    /** 发起退款 */
    boolean refund(Long payOrderId, BigDecimal amount, String reason);

    /** 查询支付单 */
    PayOrder getByPayNo(String payNo);
}

/** 支付网关接口 */
public interface IPaymentGateway {
    String channel();                        // 渠道标识：alipay / wechat
    String createPayUrl(PayRequestDTO req);  // 创建支付链接
    String queryPayStatus(String outTradeNo);// 查询支付状态
}
```

### 3.2 `twelvet-trade`（瘦身后的交易服务）

#### 保留代码

```
twelvet-trade/
├── twelvet-trade-api/
│   └── domain/
│       └── TradeOrder.java           # 交易订单实体（保留）
└── twelvet-trade-server/
    ├── controller/
    │   ├── TradeOrderController.java
    │   ├── TradePayController.java        # 内部调 IPayOrderService
    │   └── AdminMarketplaceController.java
    ├── service/
    │   ├── ITradeOrderService.java
    │   ├── impl/TradeOrderServiceImpl.java
    │   ├── IAdminMarketplaceService.java
    │   ├── impl/AdminMarketplaceServiceImpl.java
    │   ├── ICsDisputeService.java
    │   └── impl/CsDisputeServiceImpl.java
    └── mapper/
        ├── TradeOrderMapper.java
        ├── TradeLogisticsMapper.java
        ├── AdminMarketplaceMapper.java
        └── CsDisputeMapper.java
```

#### 移除代码（迁到 payment）

- `PayOrder.java` → `twelvet-payment-api/domain`
- `TenantRenewOrder.java` → `twelvet-payment-server/domain`
- `PayOrderService.java` → `twelvet-payment-server/service/impl`
- `PaymentGateway.java` → `twelvet-payment-server/service/impl`
- `AlipayGateway.java` → `twelvet-payment-server/service/impl`
- `WechatGateway.java` → `twelvet-payment-server/service/impl`
- `PaymentNotifyController.java` → `twelvet-payment-server/controller`
- `TenantRenewPayController.java` → `twelvet-payment-server/controller`
- `TenantRenewPayService.java` → `twelvet-payment-server/service/impl`
- `TenantRenewOrderMapper.java` → `twelvet-payment-server/mapper`

#### 依赖改造

`twelvet-trade-server/pom.xml` 增加：

```xml
<dependency>
    <groupId>com.twelvet</groupId>
    <artifactId>twelvet-payment-api</artifactId>
</dependency>
```

`TradeOrderServiceImpl` 等类中：

```java
// 之前（同模块直接注入）
@Autowired
private PayOrderService payOrderService;

// 之后（跨模块注入接口）
@Autowired
private IPayOrderService payOrderService;
```

### 3.3 `twelvet-runner`（新建跑腿服务）

按 [`社区跑腿模块设计方案.md`](社区跑腿模块设计方案.md) 落地。

#### 依赖

- `twelvet-framework-*`
- `twelvet-system-api`
- `twelvet-payment-api`（调支付能力）

#### 与 payment 的调用关系

```
下单付费 → RunnerTaskServiceImpl.createPaidTask()
    → IPayOrderService.createPayOrder(...)

任务确认 → RunnerTaskServiceImpl.confirmTask()
    → IPayOrderService.settle(...) 释放资金到跑腿人
    → 免费任务则加积分

退款 → RunnerTaskServiceImpl.refundTask()
    → IPayOrderService.refund(...)
```

## 四、数据库表调整

### 4.1 无需迁移

**支付表**：`PayOrder` 目前表在 trade 服务的 schema 里，重构后**不迁移数据**，只是代码搬到 payment 服务，Mapper 通过 MyBatis 访问同一张表。

**租户续费表**：同上，不迁数据。

### 4.2 跑腿新表

按方案文档三张表建：
- `twelve_runner_task`
- `twelve_runner_task_log`
- `twelve_runner_order`

## 五、执行步骤

### Step 1：新建 `twelvet-payment` 模块骨架

```bash
mkdir -p backend/twelvet-payment/twelvet-payment-api/src/main/java/com/twelvet/payment/api/{domain,enums,dto,service}
mkdir -p backend/twelvet-payment/twelvet-payment-server/src/main/java/com/twelvet/payment/server/{controller,service/impl,mapper,domain}
mkdir -p backend/twelvet-payment/twelvet-payment-server/src/main/resources
```

创建 3 个 pom.xml：
- `twelvet-payment/pom.xml`（聚合）
- `twelvet-payment-api/pom.xml`（仅依赖 framework-core）
- `twelvet-payment-server/pom.xml`（依赖 api + framework-security + payment SDK）

### Step 2：迁移支付代码

从 `twelvet-trade-server` 剪切以下文件到 `twelvet-payment-server`：

| 原路径 | 新路径 |
|--------|--------|
| `domain/PayOrder.java` | 迁到 `twelvet-payment-api/domain/` |
| `domain/TenantRenewOrder.java` | `twelvet-payment-server/domain/` |
| `service/PayOrderService.java` | `twelvet-payment-server/service/impl/PayOrderServiceImpl.java`（改造） |
| `service/PaymentGateway.java` | `twelvet-payment-server/service/impl/PaymentGatewayImpl.java`（改造） |
| `service/AlipayGateway.java` | `twelvet-payment-server/service/impl/AlipayGatewayImpl.java`（改造） |
| `service/WechatGateway.java` | `twelvet-payment-server/service/impl/WechatGatewayImpl.java`（改造） |
| `service/TenantRenewPayService.java` | `twelvet-payment-server/service/impl/TenantRenewPayServiceImpl.java` |
| `controller/PaymentNotifyController.java` | `twelvet-payment-server/controller/` |
| `controller/TenantRenewPayController.java` | `twelvet-payment-server/controller/` |
| `mapper/TenantRenewOrderMapper.java` | `twelvet-payment-server/mapper/` |

同时在 `twelvet-payment-api` 中定义接口：
- `IPayOrderService`
- `IPaymentGateway`
- `IAlipayGateway`
- `IWechatGateway`
- `ITenantRenewPayService`

**注意**：原代码里 `PaymentGateway` 等类既是实现又是接口，需要拆分为接口（api 模块）+ 实现（server 模块）。

### Step 3：更新 trade 服务

1. `twelvet-trade-server/pom.xml` 移除支付相关依赖，增加 `twelvet-payment-api` 依赖
2. 删除已迁移的文件
3. 修改 `TradeOrderServiceImpl`、`TradePayController` 中的注入：

```java
// 从
@Autowired private PayOrderService payOrderService;
// 改为
@Autowired private IPayOrderService payOrderService;
```

### Step 4：新建 `twelvet-runner` 模块

```bash
mkdir -p backend/twelvet-runner/twelvet-runner-api/src/main/java/com/twelvet/runner/api/...
mkdir -p backend/twelvet-runner/twelvet-runner-server/src/main/java/com/twelvet/runner/server/...
```

按 [`社区跑腿模块设计方案.md`](社区跑腿模块设计方案.md) 落地代码。

### Step 5：更新根 pom.xml

在 `<modules>` 下增加：

```xml
<module>twelvet-payment</module>
<module>twelvet-runner</module>
```

在 `<dependencyManagement>` 中增加两个服务的依赖版本声明。

### Step 6：更新 admin 启动入口

检查 `twelvet-admin` 启动类的 `@SpringBootApplication` 是否扫描所有包，如：

```java
@SpringBootApplication(scanBasePackages = "com.twelvet")
```

如是，无需修改；如按模块指定包名，需追加新包路径。

### Step 7：编译验证

```bash
cd backend
mvn clean install -DskipTests
```

确保无编译错误。

### Step 8：数据库 DDL 执行

按跑腿方案文档的 3 张表 DDL 执行。

### Step 9：联调测试

- 支付流程（下单 → 支付 → 回调 → 结算）
- 跑腿流程（发布 → 接单 → 完成 → 资金到账）
- 租户续费流程
- 退款流程

### Step 10：Git 提交推送

```bash
git add backend/ pom.xml docs/
git commit -m "refactor: 拆分支付服务 twelvet-payment，新建跑腿服务 twelvet-runner"
git push
```

## 六、风险与缓解

| 风险 | 缓解方案 |
|------|---------|
| 现有 PayOrderService 引用点遗漏 | 全项目 grep 定位所有引用，逐个改 |
| 事务边界变化（跨模块调支付） | 支付服务内部处理事务，trade 服务不跨模块事务；回调场景异步 |
| 支付回调地址变化 | 配置项化，回调 URL 走配置中心或 `application.yml` |
| MyBatis Mapper 扫描路径 | 检查 `@MapperScan` 是否覆盖新包路径 |
| 单元测试失效 | 迁移后重跑现有支付相关测试 |
| 前端接口路径变化 | 支付回调/租户续费接口的 URL 需前端同步更新 |

## 八、回滚方案

