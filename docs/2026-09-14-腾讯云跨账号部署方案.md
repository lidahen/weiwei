# 腾讯云跨账号 2×2C2G 部署方案

> 场景：两个腾讯账号各领 1 台 2C2G（CVM 或轻量应用服务器），跑 Weiwei 项目。
> 架构：A 主站机（nginx + backend + redis）+ B 数据/AI 机（mysql + ai-service）
> 前置阅读：`2026-09-14-2x2c2g-部署方案.md`

---

## 0. 腾讯云关键概念对照

| 概念 | 腾讯云名 | 阿里云对应 | 说明 |
|---|---|---|---|
| 云主机 | **CVM** | ECS | 同地域跨账号互通首选 |
| 轻量主机 | **轻量应用服务器** | 轻量应用服务器 | 默认 VPC 隔离，互通方式不同 |
| 虚拟网络 | **VPC** | VPC | 私有网络 |
| 子网 | **子网** | vSwitch | VPC 内的网段划分 |
| 防火墙 | **安全组** | 安全组 | 无状态，只配入站 |
| 跨账号互通 | **对等连接 PeeringConnection** | 对等连接 | 同账号也叫对等连接 |
| 跨 VPC 互通（同账号） | **云联网 CCN** | CEN | 跨账号不能用 |
| 对等连接跨账号 | **对等连接（接受方）** | 同 | ✅ 支持 |
| 对象存储 | **COS** | OSS | 备份落这里 |

## 1. 第一步：领机器前先规划网段（最重要）

⚠️ **这一步必须最先做。建完 VPC / CVM 后网段就改不了，错了要重建。**

### 默认 VPC 网段陷阱

腾讯云创建 VPC 时默认网段是 `172.16.0.0/12`（很大，包含 172.16–172.31）。**两个账号的 VPC 网段不能重叠**，否则对等连接建不起来。

### 推荐规划

```
账号 A（主账号）：
  VPC 名：vpc-web
  CIDR：  10.0.0.0/16
  子网：  10.0.1.0/24（华东广州 zone1）

账号 B（活动账号）：
  VPC 名：vpc-data
  CIDR：  10.1.0.0/16
  子网：  10.1.1.0/24（同地域同可用区）
```

**两个网段都不能是 `172.16.0.0/12` 这种大段，必须自定义小段。**

### 地域选择

两台必须**同地域**（推荐「广州」或「上海」），否则对等连接不支持，只能走公网。

## 2. 第二步：创建 VPC + 子网 + CVM

### 账号 A 操作

1. 控制台 → **网络 → VPC** → 创建
   - 名称：`vpc-web`
   - 主网卡网段：`10.0.0.0/16`
   - 子网：`10.0.1.0/24`，可用区 `ap-guangzhou-3`（或就近选）
2. 控制台 → **CVM → 创建实例**
   - 计费：活动价 / 按月
   - 规格：2C2G（推荐 SA3 / S5 / C6 系列）
   - 镜像：Ubuntu 22.04 64 位
   - 网络：选 `vpc-web`，子网 `10.0.1.0/24`
   - 公网：分配公网 IPv4（带宽 5Mbps，按量付费）
   - 安全组：见下节
   - 根磁盘：40GB SSD（默认）
3. 记录**内网 IP**（如 `10.0.1.10`）和**公网 IP**（如 `1.2.3.4`）

### 账号 B 操作

1. VPC 创建 `vpc-data`，网段 `10.1.0.0/16`，子网 `10.1.1.0/24`
2. CVM 创建 2C2G，选 `vpc-data`
3. **不要分配公网 IP**（或带宽 0）
4. 记录**内网 IP**（如 `10.1.1.20`）

> 如果领的是**轻量应用服务器**而非 CVM：轻量服务器有自己的 VPC，跨账号互通需要先把轻量服务器加入对等连接，且轻量 VPC 网段是固定的（`172.25.160.0/24` 等小段），**两台轻量不能同网段**——所以轻量方案互通比较麻烦，强烈建议换 CVM。

---

## 3. 第三步：安全组配置（最关键）

腾讯云安全组**无状态**，配入站规则即可，出站默认放行。

### 账号 A 的安全组（A 机所在）

控制台 → 网络 → 安全组 → 编辑入站规则：

| 优先级 | 协议端口 | 来源 | 策略 | 备注 |
|---|---|---|---|---|
| 1 | 80, 443 | `0.0.0.0/0` | 允许 | Web 入口 |
| 2 | 22 | 你的家庭/办公 IP | 允许 | SSH，限源 |
| 3 | 全部 | `0.0.0.0/0` | 拒绝 | 兜底 |

### 账号 B 的安全组（B 机所在）

| 优先级 | 协议端口 | 来源 | 策略 | 备注 |
|---|---|---|---|---|
| 1 | 3306 | `10.0.1.10/32` | 允许 | 仅 A 连 MySQL |
| 2 | 8001 | `10.0.1.10/32` | 允许 | 仅 A 调 AI |
| 3 | 22 | 你的家庭/办公 IP | 允许 | SSH |
| 4 | 全部 | `0.0.0.0/0` | 拒绝 | 兜底 |

> ⚠️ 3306/8001 的源**绝对不能写 0.0.0.0/0**，会被全球爆破。必须精确到 A 的内网 IP。

---

## 4. 第四步：建对等连接（跨账号）

腾讯云叫「对等连接 PeeringConnection」，跨账号支持。**由一方发起，另一方接受。**

### 账号 A（发起方）

1. 控制台 → **网络 → 对等连接** → 创建对等连接
2. 填写：
   - 名称：`peer-A-to-B`
   - 本端 VPC：`vpc-web`（账号 A 的）
   - **对端账号类型**：选择「其他账号」
   - **对端账号 ID**：账号 B 的腾讯云账号 ID（即「账号 ID」，从账号 B 控制台右上角「账号信息」复制）
   - **对端 VPC 名/ID**：从账号 B 那里获取 `vpc-data` 的 VPC 名称或 ID
3. 提交后，对等连接状态变成「等待对方接受」

### 账号 B（接受方）

1. 控制台 → **网络 → 对等连接** → 接受对等连接
2. 找到 `peer-A-to-B`，点「接受」
3. 状态变成「使用中」

> 如果控制台里看不到「接受对等连接」入口：确认账号 B 的「账号 ID」和「VPC 名称/ID」填写完全正确，大小写敏感。

---

## 5. 第五步：配置路由表（最容易漏的一步）

对等连接建好只是「通道打通」，VPC 路由表里必须告诉路由器「访问对端网段走对等连接」。

### 账号 A 路由表

1. 控制台 → VPC → `vpc-web` → 路由表 → 编辑路由项
2. 新增：
   - 目标网段：`10.1.0.0/16`（账号 B 的 VPC 网段）
   - 下一跳类型：对等连接
   - 下一跳：`peer-A-to-B`
   - 优先级：20

### 账号 B 路由表

1. 控制台 → VPC → `vpc-data` → 路由表 → 编辑路由项
2. 新增：
   - 目标网段：`10.0.0.0/16`
   - 下一跳类型：对等连接
   - 下一跳：`peer-A-to-B`
   - 优先级：20

**两边都必须加路由，缺一边就不通。**

## 6. 第六步：验证网络互通

在 A 机执行：

```bash
# 1. 测对端 VPC 内是否可达（用对端 CVM 内网 IP）
ping -c 3 10.1.1.20

# 2. 测 3306 端口（要等 MySQL 起来后才能通）
telnet 10.1.1.20 3306
# 或
nc -zv 10.1.1.20 3306

# 3. 测 AI 服务端口
curl -v http://10.1.1.20:8001/docs
```

三条都通才算网络打通。

### 不通的排查清单

| 现象 | 原因 | 解决 |
|---|---|---|
| ping 不通 | 对等连接没接受 / 路由表没配 | 检查 4、5 步 |
| ping 通但 telnet 3306 不通 | 安全组没放行 | 检查账号 B 安全组入站规则 |
| 3306 通但 8001 不通 | 同上，少配了 8001 | 加一条规则 |
| ping 通、端口也通，应用连不上 | MySQL 监听地址是 127.0.0.1 | compose 里加 `--bind-address=0.0.0.0` |
| 内网 IP 是 172.25.x.x | 你建的是轻量应用服务器 | 换 CVM 重建 |

## 7. 第七步：后端配置改内网指向

### 账号 A：`compose/a/backend/application-pro.yml`

```yaml
spring:
  datasource:
    url: jdbc:mysql://10.1.1.20:3306/twelvet-fast?allowPublicKeyRetrieval=true&useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&serverTimezone=GMT%2B8
    dynamic:
      datasource:
        slave:
          url: jdbc:mysql://10.1.1.20:3306/twelvet-fast?...

ai:
  service:
    url: http://10.1.1.20:8001
```

### 账号 B：`compose/b/ai-service/.env`

```ini
DATABASE_URL=mysql+aiomysql://root:***@mysql:3306/twelvet-fast
# 容器内通过 compose 服务名 mysql 连本机 MySQL
```

### 账号 B：`compose/b/docker-compose.yml`

MySQL 加监听地址：
```yaml
command:
  - --bind-address=0.0.0.0          # 关键，默认 127.0.0.1
  - --character-set-server=utf8mb4
  - --collation-server=utf8mb4_unicode_ci
  - --innodb-buffer-pool-size=384M
  - --innodb-log-file-size=128M
  - --innodb-flush-log-at-trx-commit=2
  - --max-connections=50
```

## 8. 跨账号备份脚本

账号 B 的 mysqldump 备份脚本（在 B 机跑），落本地后定期上传到**账号 B 的 COS**：

```bash
#!/usr/bin/env bash
set -euo pipefail
TS=$(date +%Y%m%d-%H%M%S)
OUT=/opt/weiwei/backup/db_${TS}.sql.gz
docker exec weiwei-mysql-1 sh -c "mysqldump -uroot -p'${MYSQL_ROOT_PASSWORD}' \
  --all-databases --single-transaction --routines --triggers --skip-comments" \
  | gzip > "$OUT"
find /opt/weiwei/backup -name 'db_*.sql.gz' -mtime +7 -delete
# 上传到 COS（账号 B）
/usr/local/bin/coscli cp "$OUT" cos://weiwei-backup/db/${TS}.sql.gz
echo "backup ok: $OUT"
```

COS 上传工具 `coscli`：https://cloud.tencent.com/document/product/436/37734

crontab：
```cron
0 3 * * * /opt/weiwei/compose/b/scripts/backup.sh >> /opt/weiwei/backup/cron.log 2>&1
```

### 关于 OSS/COS 跨账号问题

如果 OSS/COS bucket 在账号 A，账号 B 要传备份到账号 A 的 bucket，需要做 **COS 跨账号授权**：
1. 账号 A 的 COS bucket 配置「访问控制 → Bucket 策略」
2. 添加规则：允许账号 B 的 UIN 上传到指定前缀
3. 账号 B 的 CAM 用户配置对应密钥

**更简单的做法**：COS 建在账号 B（跟 MySQL 同账号），备份脚本上传同账号 COS 不用额外授权。账号 A 的 OSS 密钥用于业务文件存储，跟备份无关。

## 9. 跨账号 SSH 互通（可选，方便管理）

如果想从 A 直接 `ssh B` 管机器，免输密码：

```bash
# 在 A 上生成密钥（如果还没有）
ssh-keygen -t ed25519

# 把公钥放到 B 的 authorized_keys（先用临时密码或控制台 SSH 登录 B 一次）
ssh-copy-id -i ~/.ssh/id_ed25519.pub ubuntu@10.1.1.20

# 之后
ssh ubuntu@10.1.1.20
```

## 10. 跨账号监控

腾讯云两个账号的「云监控」是独立的，看不到对方的告警。

**简单方案**：每个账号各自建监控告警，通过「通知策略 → 微信/邮件」推给你同一个手机号。

**进阶方案**：装 Prometheus + Node-Exporter 在两台机器上，**Prometheus 部署在账号 A**，scrape 两台：

```yaml
# /opt/prometheus/prometheus.yml
scrape_configs:
  - job_name: 'weiwei'
    static_configs:
      - targets:
          - '10.0.1.10:9100'   # A 机
          - '10.1.1.20:9100'   # B 机（通过内网）
    scrape_interval: 15s
```

但这会增加 A 机内存 200m+，2C2G 不建议。**简单方案足够。**

## 11. 费用对照

| 项 | 同账号 | 跨账号 |
|---|---|---|
| 对等连接流量费 | 0（免费额度） | 0（同地域内网免费） |
| 公网带宽 | 按实际 | 按实际 |
| COS 跨账号 | 同账号流量费 | **跨账号流出流量 ¥0.5/GB** |
| 账单 | 1 张 | 2 张 |

跨账号的**唯一额外成本**是 COS 跨账号流出流量。如果备份落账号 B 的 COS，跟账号 A 完全解耦，零额外成本。

## 12. 上线 Checklist（跨账号版）

### 网络（必须先做）
- [ ] 两个 VPC 网段不重叠（10.0.0.0/16 vs 10.1.0.0/16）
- [ ] 两台 CVM 同地域同可用区
- [ ] 对等连接 A 发起、B 接受，状态「使用中」
- [ ] 两边 VPC 路由表都加了对端网段路由
- [ ] 安全组按上述规则配置完成
- [ ] A 机 telnet B 机的 3306 / 8001 通

### 应用
- [ ] `application-pro.yml` 用 B 机内网 IP
- [ ] MySQL `--bind-address=0.0.0.0`
- [ ] 补 2 个 Dockerfile（backend、ui）
- [ ] 拆 compose 为 `compose/a/`、`compose/b/`
- [ ] MySQL root 密码改 16 位随机
- [ ] OSS accessKey/secretKey 用 Jasypt 加密或环境变量
- [ ] swagger 关闭
- [ ] 备份脚本 + cron + COS 上传

### 验证
- [ ] A 机空闲内存 ≥ 500m，B 机 ≥ 600m
- [ ] 核心接口 p95 < 500ms
- [ ] IM WebSocket 1 小时不断
- [ ] AI 图片生成成功率 ≥ 95%
- [ ] 重启 A 机不影响 B；重启 B 机 backend 自动重连

## 13. 常见踩坑速查

| 问题 | 原因 | 解决 |
|---|---|---|
| 对等连接创建失败：VPC 网段冲突 | 两个 VPC 用了 172.16.0.0/12 | 必须重建 VPC，网段改小 |
| 对等连接创建后状态「等待接受」 | 账号 B 没接受 | 账号 B 控制台接受 |
| 控制台找不到对等连接 | 账号 B 没填对账号 ID | 检查 VPC 名称和账号 ID |
| ping 通但端口不通 | 安全组入站规则没加 | 账号 B 安全组加规则 |
| telnet 3306 通但应用报认证失败 | MySQL 用户权限只允许 localhost | 改 my.cnf 或建 root@'%' 用户 |
| 后端连不上 MySQL：Communications link failure | MySQL 监听 127.0.0.1 | `--bind-address=0.0.0.0` |
| 轻量应用服务器不能跨账号互通 | 轻量 VPC 不支持对等连接 | 换 CVM |
| COS 上传报 Forbidden | 跨账号 COS 没授权 | 用账号 B 的 COS |

## 14. 一句话总结

腾讯云跨账号 2×2C2G：
1. **建 VPC 时网段不能重叠**（10.0/16 vs 10.1/16，不能用默认 172.16/12）
2. **建对等连接**（A 发起，B 接受）
3. **两边路由表都加对端网段路由**
4. **安全组只放行对方内网 IP 的 3306/8001**
5. **MySQL 监听 0.0.0.0**

做完 1–5 步，`telnet 10.1.1.20 3306` 通就成。

**领机器前务必规划网段，否则重建成本极高。**
