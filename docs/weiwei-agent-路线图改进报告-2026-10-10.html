二、改进 1：结构化 trace（可观测性）

改动文件：state.py（新增 trace 字段）、nodes.py（工具循环采集）、runner.py（汇总输出）。

  • 采集内容：LLM 调用次数与累计耗时（llm_calls / llm_ms）、每次工具调用明细（名称 / 成败 / 耗时 ms / 结果长度 / 错误）、意图、置信度、token 用量、总延迟、是否 interrupt 挂起。
  • 输出方式：runner 在图执行结束后输出单行 JSON 日志（agent_trace {...}），可直接 grep / 接入日志采集。
  • 安全设计：trace 收集自身全部包在 try/except 中，序列化失败只降级为 debug 日志，绝不影响主流程。
日志示例：
agent_trace {"event":"agent_trace","session_id":"s1","intent":"checkout","confidence":0.92,
  "llm_calls":2,"llm_ms":1840,"tool_calls":[{"tool":"search_products","ok":true,"ms":120,...}],
  "usage":{"input_tokens":812,"output_tokens":156},"latency_ms":2311,"interrupted":false}

价值：失败归因可定位到具体环节（路由误判 / 工具超时 / LLM 异常），这正是路线图"会看 trace，定位失败在 prompt、工具、检索、模型还是状态管理"的落地。

三、改进 2：路由评测集（评测先行）

新增文件：tests/agent_eval/router_cases.json、tests/agent_eval/run_router_eval.py、tests/test_agent_eval.py。

  • 26 条标注用例：覆盖全部 11 个意图（每意图 2–4 条），含指代消解（"第二款/就买这个"）、跨轮购买意向、无字面关键词的售后场景（"书是盗版的"）、模糊输入→澄清（"帮我搞一下"）。
  • 双模式脚本：离线模式（无需 API Key）校验用例结构、意图清单与域映射一致性；在线模式（--online）真实调用 router_node，输出准确率、混淆分布、失败分类（意图误判 / 置信度不足 / 误分发），报告写入 report_<ts>.json。
  • 防腐化测试：3 条 pytest 保证评测集始终 ≥20 条、结构合法、意图全覆盖——防止评测集本身腐化。
上线基线运行（在服务环境执行）：
  python tests/agent_eval/run_router_eval.py --online
  通过线：准确率 ≥ 85%（脚本 exit 0）
