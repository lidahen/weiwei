## 1. 目标

1. 任务确认完成（completed）后，发布者可对接单人进行 1-5 星评价 + 文字评语。
2. 基于评价 + 订单数据实时计算跑腿员信用画像（不加信用冗余表）。
3. 评价成功后复用 IM 通知机制（RunnerTaskNotifyEvent + RunnerTaskNotifyListener）通知被评价方。
4. 前端任务详情页：completed 状态给发布者"评价"入口；所有人可查看接单人信用摘要（平均分 + 完成单数）。
5. 不破坏现有接口契约，全部为新增字段/新增接口。

## 2. 信用计算方案（务实选型：不新增信用表，SQL 实时聚合）

**不加冗余信用表/字段**。理由：跑腿单量目前极小（演示级），实时聚合开销可忽略；冗余分数需要维护一致性与重算 job，复杂度不划算。若未来单量大（>10w 评价），再引入 `twelve_runner_credit` 快照表 + 定时重算（见遗留 TODO）。

- **平均分**：`AVG(rating)` from `twelve_runner_review WHERE runner_id=?`
- **完成单数**：`twelve_runner_task WHERE assignee_id=? AND status='completed'`
- **总接单数 totalCount**：`twelve_runner_task WHERE assignee_id=? AND assign_time IS NOT NULL`（接到手的单，accepted 之后任何终态）
- **近30天完成率**：近30天该跑腿员 `runner_order` 接单数 vs 对应任务完成数（`completed_30d / accepted_30d`，无接单记 null）
- **异常单数 penalizedCount**：`twelve_runner_task WHERE assignee_id=? AND status IN ('cancelled','refund','disputed')`
  （接到手后被取消 / 退款中 / 纠纷，均算异常；`penalizedCount30d` 为近30天口径，按 `assign_time` 过滤。
  "超时未接单"自动取消的任务无接单人，不计入；当前状态机不存在"接单后超时"终态，若未来新增，将其并入 IN 列表即可）
- **信用分 creditScore（0-100）**：

  ```
  base        = avgRating × 20          （无评价默认 80，新人保护）
  rate        = completedCount30d / acceptedCount30d   （近30天无接单记 1.0，中性不奖不罚）
  creditScore = clamp(0, 100, round(base × (0.7 + 0.3 × rate)) − 5 × penalizedCount30d)
  ```

  即：**完成率因子** 0.7+0.3×rate（完成率 0 → 最低打 7 折；1.0 → 不折；无接单 → 不折不扣）；
  **异常单惩罚** 近30天每笔异常单扣 5 分（线性累加，无上限，最终 clamp 到 [0,100]）。
  示例：5 星 + 完成率 1.0 + 无异常 → 100；5 星 + 完成率 0.67 + 1 笔异常 → 100×0.9−5 = 85；
  无评价 + 0% 完成率 + 1 笔异常 → 80×0.7−5 = 51。

**大厅排序**：大厅列出的是待接任务（无接单人），任务本身没有信用属性，改任务排序无意义。因此**保持 `/runner/hall` 现有排序（create_time DESC）不变**；在任务详情页展示接单人信用摘要，并在接单人"我接的任务"页展示自己的信用画像，供跑腿员维护信用。未来若做"跑腿员推荐列表"，用 creditScore DESC 排序（接口已支持按 userId 取分）。

## 3. 表设计

```sql
CREATE TABLE IF NOT EXISTS `twelve_runner_review` (
    `id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '评价ID',
    `tenant_id`    BIGINT       NOT NULL DEFAULT 1 COMMENT '租户ID',
    `task_id`      BIGINT       NOT NULL COMMENT '任务ID',
    `order_id`     BIGINT       DEFAULT NULL COMMENT '关联接单记录ID（twelve_runner_order.id）',
    `task_no`      VARCHAR(32)  COMMENT '任务编号（冗余，便于查询）',
    `publisher_id` BIGINT       NOT NULL COMMENT '评价人（任务发布者）',
    `runner_id`    BIGINT       NOT NULL COMMENT '被评价人（接单跑腿员）',
    `rating`       TINYINT      NOT NULL COMMENT '评分 1-5 星',
    `tags`         VARCHAR(200) COMMENT '评价标签（逗号分隔，可选）',
    `content`      VARCHAR(500) COMMENT '评语',
    `create_time`  DATETIME     DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_task` (`tenant_id`, `task_id`),
    KEY `idx_runner` (`tenant_id`, `runner_id`),
    KEY `idx_publisher` (`tenant_id`, `publisher_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='跑腿任务评价';
```

防刷核心：`UNIQUE KEY uk_task(tenant_id, task_id)` —— 一任务只能被评一次（DB 层兜底）。

## 4. 接口设计

### 4.1 提交评价（新增）
`POST /runner/task/{id}/review`（需登录，X-Tenant-Code）
```json
{ "rating": 5, "content": "很快送达，好评！", "tags": "准时,态度好" }
```
校验（防刷规则）：
1. 仅任务发布者本人可评（publisher_id = 当前登录人）
2. 任务状态必须是 `completed`（确认完成后才能评价，pending_confirm 也不行）
3. 一任务一评（先查 uk，再靠 DB 唯一键兜底并发）
4. rating 必须 1-5；content ≤ 500 字
5. 返回：`{reviewId, creditScore}`（评价后跑腿员最新信用分）

### 4.2 信用画像（新增）
`GET /runner/credit/{userId}`
```json
{
  "userId": 108,
  "completedCount": 4,
  "totalCount": 6,
  "completedCount30d": 4,
  "acceptedCount30d": 6,
  "completionRate30d": 0.67,
  "penalizedCount": 1,
  "penalizedCount30d": 1,
  "avgRating": 5.0,
  "reviewCount": 1,
  "creditScore": 85,
  "hasData": true
}
```
无任何数据时给默认：`creditScore=80, hasData=false, avgRating=null`（若该用户存在异常单，
仍会按公式在默认 80 基础上打折/扣分）。

### 4.3 通知（复用现有机制）
评价成功后发布 `RunnerTaskNotifyEvent(taskId, "review", publisherId, "<N>星", tenantId)`，
`RunnerTaskNotifyListener` 新增 `ACTION_REVIEW` 分支：通知接单人
"【跑腿】任务「xxx」获得 N 星好评，信用分已更新"。异步发送，失败仅落 notify_log，不影响评价事务。

## 5. 前端改动（ui/src/pages/Runner/，最小改动）

- `services/runner/api.ts`：新增 `taskReview(id, data)`、`runnerCredit(userId)`。
- `Detail.tsx`：
  - 发布者 + completed 状态 → 显示"评价"按钮 → Modal（Rate 打星 + TextArea 评语），成功后刷新；
  - 已有评价（任务已评）→ 展示星级与评语；
  - 有接单人时 → 信用摘要卡片（平均分 / 完成单数 / 信用分），发布者与跑腿员/他人均可见。
- 不改 Hall / MyTaken 等页面契约。
