# 移动端适配体检报告

> 体检日期：2026-09-23 ｜ 范围：`ui/`（React + Umi max + Ant Design Pro + antd-style）
> 方法：全量路由盘点 + 逐类静态扫描（媒体查询 / 栅格断点 / 固定宽度 / 表格 / 弹窗 / flex 布局）+ 代表性页面精读。未改任何代码。

---

## 一、总结论

**全站 57 个页面中，仅 3 处做过移动端适配（首页、登录页、页脚），其余全部为桌面优先写法。**
手机上打开任何非首页页面都会遇到内容横向溢出、双栏挤压、表格横滚、聊天区高度错位等问题，「没法用」的体验与代码现状一致。

好消息是：**viewport 配置正确、商品卡片等共享组件是流体宽度、技术栈（antd-style createStyles）天然支持媒体查询**——适配是「补课」而非「重构」，风险可控。

## 五、适配策略建议（分期路线）

### 总原则
1. **断点收敛**：统一为两档——`<768px` 为移动端，`≥768px` 维持现有桌面布局。把现存 768/899/1024 逐步归拢。
2. **技术方案与现状一致**：项目已用 `antd-style createStyles`（Home/Footer/Login 已示范写法），继续用它补 `@media`，不引入新框架，每页改动是「加样式」而非「改结构」。
3. **C 端做真适配，后台做兜底**。

### 分期计划

| 期 | 内容 | 关键动作 | 规模预估 |
|---|---|---|---|
| **P0-壳**（先做，全局受益） | 布局壳移动化 | ① 手机端隐藏桌面 Footer，新增**底部 TabBar**（首页/动态/发布/消息/我的）；② PageContainer 手机端压缩标题/留白；③ 断点常量收敛到 `styles/tokens.ts` | 新增 1 组件 + app.tsx 配置 |
| **P0-交易链路** | 12 页核心链路 | 商品详情双栏改单栏、Descriptions 精简、OrderList/跑腿表格**改卡片列表**（手机端体验关键）、Chat 高度改 `100dvh` + 输入栏适配安全区 | 约 12 页 |
| **P1-发布与个人** | 17 页 | 栅格补 xs、发布表单单列化、跑腿表格同 P0 改卡片 | 约 17 页 |
| **P2-AI 工具** | 约 8 页 | 聊天类统一高度方案、生成器页面栅格补 xs | 约 8 页 |
| **P3-后台兜底** | 38 页 | 仅全局规则：表格横滚（global.less 已有雏形，需加固）、Modal 宽度 `min(92vw, 原宽)`、搜索表单竖排 | global.less + 少量公共组件 |

### 每页的标准改造清单（供执行时对照）

- [ ] 页面主容器 padding 收敛为 `16px`（桌面维持 24px）
- [ ] `Row/Col` 补 `xs={24}`（或改 flex + wrap）
- [ ] 多列操作区加 `flexWrap`，`gap ≥ 24` 的降到 12~16
- [ ] Table/ProTable 页面：手机端换卡片列表，或至少 `scroll={{ x: ... }}`
- [ ] 聊天/满屏页高度改 `100dvh` 并重算头部扣除
- [ ] Modal 宽度加 `width: 'min(92vw, 640px)'` 类兜底
- [ ] 底部 TabBar 页面预留 `padding-bottom: env(safe-area-inset-bottom)`

## 六、风险与依赖

| 风险 | 说明 | 对策 |
|---|---|---|
| ProLayout 抽屉与 TabBar 叠加 | 手机端 ProLayout 侧栏抽屉仍可打开，与 TabBar 并存需理顺导航层级 | TabBar 承载 C 端入口，侧栏仅保留后台菜单（按角色区分） |
| GSAP 动画窄屏表现 | 首页入场动画未在窄屏验证 | P0 实测，必要时 `matchMedia` 降级 |
| `100dvh` 兼容性 | iOS Safari 15.4+/现代安卓支持良好，旧机型需 `100vh` 回退 | CSS 双写回退 |
| 构建与发布链路 | 改完必须重新 build + 上传 + `chown -R caddy:caddy`（生产部署惯例） | 纳入每期收尾 |
| 工作量集中 | P0+P1 约 29 页，逐页手改较重 | 建议按 P0-壳 → P0-交易 → P1 分三个独立提交推进，每期手机端回归一遍核心链路 |
