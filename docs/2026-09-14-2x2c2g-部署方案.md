# Weiwei 2×2C2G 部署方案：主站机 + 数据/AI 机

> 适用场景：社区二手交易「自营打样」阶段，1–3 个小区试点，预估 < 200 在线 / 50 并发。
> 不适用：单点 SLA > 99.9% 的对外业务（需 3+ 节点 + 主从 + SLB，本方案不覆盖）。

---

## 1. 架构总览

```
                       用户
                        │
                        ▼
        ┌───────────── 机器 A：主站机（公网入口） ─────────────┐
        │                                                      │
        │   Nginx :80 / :443                                   │
        │     ├── /            → 静态产物 (ui/dist)           │
        │     ├── /api         → backend :8080               │
        │     └── /im          → backend :8080 (WebSocket)   │
        │                                                      │
        │   backend   (twelvet-admin.jar)   -Xmx768m         │
        │   redis:7-alpine  :6379                                 │
        │                                                      │
        │   出站：访问机器 B 的 :3306 / :8001                 │
        └──────────────────────────────────────────────────────┘
                              │ 同 VPC 内网
        ┌───────────── 机器 B：数据 + AI ───────────────────┐
        │                                                      │
        │   MySQL 8.0  :3306   (仅内网白名单，不暴露公网)    │
        │   ai-service :8001   (FastAPI + faiss-cpu)         │
        │                                                      │
        │   cron: mysqldump 每日备份                          │
        └──────────────────────────────────────────────────────┘
```

**关键设计原则**
1. MySQL 与 AI 是内存大户（MySQL 400–800m，faiss+langchain 300–500m），单独放一台，主站机才稳。
2. AI 调用（图片/视频/RAG）是异步慢操作，与用户浏览流量隔离，互不拖慢。
3. MySQL 不暴露公网，安全边界清晰；只在内网对 A 开放 3306。
4. 两台机器各自独立重启：改后端代码不动数据库，扩容 AI 不动 Web。

## 2. 内存预算

| 机器 | 组件 | 估算 | 上限 |
|---|---|---|---|
| **A** | OS + Docker daemon | 300m | |
| | backend `-Xmx768m` | 1.1g | |
| | redis:7-alpine | 80m | |
| | nginx + ui 静态 | 50m | |
| | **合计** | **~1.55g** | **≤1.8g（85%）** |
| **B** | OS + Docker daemon | 300m | |
| | MySQL 8.0（buffer pool 384m） | 650m | |
| | ai-service（uvicorn 单 worker） | 450m | |
| | **合计** | **~1.4g** | **≤1.7g（85%）** |

两台都留 500–600m 余量，足以承接突发登录高峰或一次批量 AI 图片生成。

**强制加 swap**（2G 机器最便宜的保险）：
```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## 3. 前置准备

### 3.1 云服务器
- 同区域同 VPC，安全组允许 A ↔ B 内网互通。
- A 开放公网：80 / 443；B 不开放任何公网端口。
- 域名解析到 A 的公网 IP；如有 HTTPS，证书放 A 的 `/etc/nginx/ssl/`。

### 3.2 安全组规则

| 源 | 目标 | 端口 | 说明 |
|---|---|---|---|
| 公网 0.0.0.0/0 | A | 80, 443 | 仅 Web |
| A 内网 IP | B | 3306 | 仅后端连库 |
| A 内网 IP | B | 8001 | 后端调 AI |
| A 内网 IP | B | 6379 | 如果 redis 放 B（本方案放 A，无需） |

### 3.3 目录约定

```
/opt/weiwei/
├── compose/          # docker-compose.yml
├── backend/          # jar + application-*.yml
├── ai-service/       # 源码 + .env
├── ui/dist/          # yarn build 产物
├── nginx/            # nginx.conf
├── data/mysql/       # B 机持久卷
└── backup/           # B 机 mysqldump 输出
```

## 4. 机器 A：主站机

### 4.1 `compose/a/docker-compose.yml`

```yaml
version: '3.9'
services:
  nginx:
    image: nginx:1.27-alpine
    restart: always
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./ui/dist:/usr/share/nginx/html:ro
      - ./nginx/ssl:/etc/nginx/ssl:ro
    depends_on: [backend]

  backend:
    build: ./backend
    restart: on-failure:5
    environment:
      - TZ=Asia/Shanghai
      - SPRING_PROFILES_ACTIVE=pro
      - DB_HOST=<机器B内网IP>
      - AI_SERVICE_URL=http://<机器B内网IP>:8001
      - JASYPT_PASSWORD=${JASYPT_PASSWORD}
    env_file:
      - ./backend/.env
    # 端口不暴露到宿主机；由 nginx 内部网络访问
    expose: ["8080"]
    depends_on: [redis]
    deploy:
      resources:
        limits:
          memory: 1300m

  redis:
    image: redis:7-alpine
    restart: always
    command: ["redis-server", "--maxmemory", "128m", "--maxmemory-policy", "allkeys-lru"]
    expose: ["6379"]
    volumes:
      - ./data/redis:/data
    deploy:
      resources:
        limits:
          memory: 200m
```

### 4.2 `compose/a/backend/Dockerfile`（补齐项目缺失的文件）

```dockerfile
FROM eclipse-temurin:17-jre-alpine
LABEL maintainer="weiwei"

RUN apk add --no-cache tzdata curl \
    && cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime \
    && echo "Asia/Shanghai" > /etc/timezone

WORKDIR /app

COPY ./twelvet-admin/target/twelvet-admin.jar app.jar
COPY ./twelvet-admin/src/main/resources/application-pro.yml /app/application-pro.yml

ENV TZ=Asia/Shanghai \
    JAVA_OPTS="-Xms128m -Xmx768m \
               -XX:MaxMetaspaceSize=256m \
               -XX:MaxDirectMemorySize=128m \
               -XX:+UseContainerSupport \
               -XX:MetaspaceSize=128m \
               -XX:+UseStringDeduplication \
               -Dfile.encoding=UTF-8"

EXPOSE 8080

# 健康检查：Spring Actuator 需开启 health 端点；否则用 8080 TCP 探测
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD curl -fs http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar /app/app.jar"]
```

> 原项目 Dockerfile 用的是 `openjdk:17-oracle`，该镜像已 EOL，必须替换。

### 4.3 `compose/a/nginx/nginx.conf`

```nginx
worker_processes 1;
worker_rlimit_nofile 4096;

events { worker_connections 1024; }

http {
  include       /etc/nginx/mime.types;
  sendfile      on;
  tcp_nopush    on;
  keepalive_timeout 65;
  client_max_body_size 25m;     # 配合后端 max-request-size: 20MB
  gzip on;
  gzip_types text/plain text/css application/json application/javascript image/svg+xml;

  upstream backend { server backend:8080; keepalive 32; }

  server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
  }

  server {
    listen 443 ssl;
    http2 on;
    server_name ershou.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 前端静态资源
    root  /usr/share/nginx/html;
    index index.html;

    location / {
      try_files $uri $uri/ /index.html;
      add_header Cache-Control "public, max-age=600";
    }

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|webp|svg|woff2?)$ {
      expires 30d;
      add_header Cache-Control "public, immutable";
    }

    # API 反向代理
    location /api/ {
      proxy_pass http://backend/;          # 去掉 /api 前缀
      proxy_http_version 1.1;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
      proxy_read_timeout 120s;
      proxy_connect_timeout 10s;
    }

    # WebSocket（IM 模块）
    location /im/ {
      proxy_pass http://backend/im/;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      proxy_read_timeout 3600s;            # 1h 长连
    }

    # 上传体积上限
    client_body_buffer_size 128k;
  }
}
```

### 4.4 `compose/a/backend/application-pro.yml` 改造要点

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:127.0.0.1}:3306/twelvet-fast?...

      datasource:
        slave:
          url: jdbc:mysql://${DB_HOST:127.0.0.1}:3306/twelvet-fast?...

    redis:
      host: redis          # 容器网络内服务名
      port: 6379

    url: ${AI_SERVICE_URL:http://localhost:8001}
```

## 5. 机器 B：数据 + AI

### 5.1 `compose/b/docker-compose.yml`

```yaml
version: '3.9'
services:
  mysql:
    image: mysql:8.0.32
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}     # 至少 16 位随机
      MYSQL_DATABASE: twelvet-fast
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-buffer-pool-size=384M
      - --innodb-log-file-size=128M
      - --innodb-flush-log-at-trx-commit=2
      - --innodb-flush-method=O_DIRECT
      - --max-connections=50
      - --thread-cache-size=4
      - --table-open-cache=200
      - --bind-address=0.0.0.0
      - --local-infile=0
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    ports: ["3306:3306"]            # 仅安全组限制为机器 A
    expose: ["3306"]
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 15s
      timeout: 5s
      retries: 5
    deploy:
      resources:
        limits:
          memory: 900m

  ai-service:
    build: ./ai-service
    restart: on-failure:5
    env_file: ./ai-service/.env
    environment:
      - DATABASE_URL=mysql+aiomysql://root:***@mysql:3306/twelvet-fast
      - REDIS_URL=redis://redis:6379/0
      - TZ=Asia/Shanghai
    ports: ["8001:8001"]
    depends_on:
      mysql:
        condition: service_healthy
    deploy:
      resources:
        limits:
          memory: 700m
```

> 注意：本方案 redis 放机器 A，但 ai-service 需要 RediSearch（langgraph-checkpoint-redis 的 AsyncRedisSaver 要 FT 索引）。
> **二选一**：
> - **(推荐)** 把 ai-service 里的 `REDIS_URL` 改指机器 A 的 redis，但机器 A 必须用 `redis-stack-server` 而非 `redis:7-alpine`，内存上限调到 256m。
> - 或者 ai-service 自带一个本地 `redis-stack-server`（多 100–150m，机器 B 仍能塞下）。

### 5.2 备份脚本 `compose/b/scripts/backup.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
TS=$(date +%Y%m%d-%H%M%S)
OUT=/opt/weiwei/backup/db_${TS}.sql.gz
docker exec weiwei-mysql-1 sh -c "mysqldump -uroot -p'${MYSQL_ROOT_PASSWORD}' \
  --all-databases --single-transaction --routines --triggers --skip-comments" \
  | gzip > "$OUT"
# 保留 7 天
find /opt/weiwei/backup -name 'db_*.sql.gz' -mtime +7 -delete
echo "backup ok: $OUT ($(du -h "$OUT" | cut -f1))"
```

crontab：
```cron
0 3 * * * /opt/weiwei/compose/b/scripts/backup.sh >> /opt/weiwei/backup/cron.log 2>&1
```

每月至少一次冷备到 OSS（`/opt/weiwei/backup` → 阿里云 OSS），防止 B 机磁盘意外损坏。

## 6. 构建与发布流程

```bash
# 本地构建
mvn -f F:/code/weiwei/backend/pom.xml clean package -DskipTests
# 前端构建
cd F:/code/weiwei/ui && yarn install && yarn build
# ai-service 源码打包（含 .env）
tar czf ai-service.tgz -C F:/code/weiwei/ai-service .

# 上传到机器 A
rsync -avz backend/twelvet-admin/target/twelvet-admin.jar  user@<A_IP>:/opt/weiwei/compose/a/backend/jar/
rsync -avz ui/dist/                                        user@<A_IP>:/opt/weiwei/compose/a/ui/dist/
# 上传到机器 B
rsync -avz ai-service.tgz                                  user@<B_IP>:/opt/weiwei/compose/b/ai-service.tgz

# 机器 A 重启
ssh user@<A_IP> "cd /opt/weiwei/compose/a && docker compose up -d --build backend"

# 机器 B 重启 AI
ssh user@<B_IP> "cd /opt/weiwei/compose/b && docker compose up -d --build ai-service"
```

> 数据库变更走 `flyway`/手工 SQL 审核，不在 CI 里自动迁移。

## 8. 升级路径

| 触发条件 | 动作 |
|---|---|
| 在线 > 500 / p95 > 1s | A 机升 4G |
| MySQL CPU > 70% 持续 10min | B 机升 4C4G，或迁云 RDS |
| ai-service OOM | 关掉 faiss-cpu，RAG 改远程 embedding 服务；或 B 机升 4G |
| 多小区扩张 > 10 个 | 拆 3 机：Web×2（HA）+ 数据/AI |
| 单点 SLA 要求 | 上主从 MySQL + Redis Sentinel + SLB |

## 10. 一句话总结

两台 2C2G，**不要做对称 HA**，按职责拆成「Web + 数据/AI」两台。
A 跑 nginx + backend + redis，B 跑 mysql + ai-service。
两台都留 30% 余量，加 2G swap，B 机每日备份。**够支撑阶段一自营打样，复制到 10+ 小区前再升配或拆 3 机。**
