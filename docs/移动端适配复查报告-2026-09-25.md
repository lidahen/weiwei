## 一、复查总结论

**P0 核心链路（首页/搜索/商品详情/发布/AI 三大工作台）的移动端形态已经成型**：两列商品网格、底部 TabBar、抽屉菜单、纵向流式表单都正常，天气/同城已按 IP 定位城市。静态扫描报告里"没法用"的评价已不成立。

但实测仍发现 **2 个功能性 bug（内容互相重叠）**、**3 处明显体验缺陷**，且适配覆盖面依然只有一小半——`useIsMobile` 仅 9 个文件、`@media` 仅 6 个文件在用。当前"适配差"的体感主要来自：**Runner 筛选区重叠、Header 未收纳、未适配页面的占比仍然很高**。

## 三、实测新发现的问题（按严重度）

### P0 —— 功能性 bug（内容重叠/不可用）

**1. 跑腿接单大厅筛选区文字重叠**（06-runner.png）
- 现象：`价格：`标签被压成竖排两行；排序区 `Segmented(价格降序/最新发布)` 与橙色 `按价格降序` Tag **文字互相叠压**，点击区域错乱。
- 根因：`Runner/Hall.tsx:279-292` 筛选区是桌面 `Row/Col + Space`（不换行），只有任务列表走了 `isMobile` 分支（Hall.tsx:295），筛选区没有。
- 附带问题：`Segmented` 已 disabled 又叠一个同义 Tag，本身冗余。
- 修法：筛选区增加 `isMobile` 分支（标签上置、控件整行）；删掉冗余 Tag。

**2. IM 聊天页无底部 TabBar**（07-chat.png）
- 现象：其他所有页面都有 TabBar，唯独 `/im/chat` 没有，导航断了。
- 根因待查：Chat 用 `height: calc(100vh - 240px)` 硬扣高度（v1 报告已指出），疑把 footer 挤出视口或自身覆盖了 `footerRender`。
- 修法：Chat 页单独处理布局高度（`100dvh` + `env(safe-area-inset-bottom)`），确保 TabBar 常驻。

### P1 —— 明显体验缺陷

**3. Header 移动端未收纳**（所有截图）
- 现象：汉堡菜单 + logo + 铃铛 + 问号 + 语言切换 + "TwelveT"用户名文字全平铺，头占用约 1/3 宽度。
- 建议：<768px 只保留 汉堡 + logo + 铃铛 + 头像；问号/语言/用户名收进抽屉菜单或个人中心。

**4. 商品卡片卖家行拥挤**（02/03）
- 现象：`老张-数码铺 95新 深圳` 行贴边，"深圳"被裁掉一半。
- 根因：`ProductCard/index.tsx` seller 有 ellipsis 但移动端 padding/间距未收缩，城市 `flexShrink:0` 把行占满。
- 建议：移动端隐藏城市或整行降字号加间距。

**5. 地址卡与设置页细节**（13/12）
- 地址卡：手机号与"删除"按钮挤在同一行且号码截断；卡片只占半宽没有铺满。
- 设置页：底部 Tab（基本信息/修改密码）被裁一半；头像上传框直接显示 `https://weiw...` 原始 URL 文字。

### P2 —— 系统性缺口（决定"整体体感"）

**6. 覆盖面仍是少数派**
- `useIsMobile`：9 个文件；`@media`：6 个文件。
- 完全没有适配代码的 C 端页面：Chat、ConversationList、Pay、PayResult、OrderDetail、RefundApply/Detail、Ship、Review、FeedDetail、UserFavorites/Follows/Settings、AI 的 Doc/Knowledge/Butler/DailyReport/Mcp/Model/ShoppingGuide；admin/cs 后台全部。
- 其中 Pay/Refund/Ship/Review 是交易闭环，手机上用不了就是业务断点。

**7. antd 组件全是桌面形态**
- Select 下拉（搜索筛选、发布页成色等）是桌面小弹层，移动端应换大触控面板/底部弹层；Modal、Descriptions、Table 同理。缺一份「移动端组件替换规范」，各页各自为战。

**8. 安全区与触控目标**
- `safe-area-inset-bottom` 只有 MobileTabBar/AiGuideFloat 处理；页面级底部提交按钮（发布动态等）没有留 Home 指示条空间。
- 「不感兴趣」× 按钮 22px、各种 Tag 点击区 <44px，不满足最低触控标准。

**9. 断点未收敛**
- `tokens.mq` 已建但使用率低；代码里仍散落 767/768/899/1024 多种写法（v1 遗留问题，未解决）。

## 四、优化路线建议（三期）

**第一期（修 bug，约 1 天）**：Runner 筛选区移动分支 + 删冗余 Tag；Chat 页 TabBar/高度；Header 收纳；卡片卖家行、地址卡、设置页细节。全部是局部小改，收益立竿见影。

**第二期（补覆盖，3~5 天）**：交易闭环剩余页（Pay → PayResult → OrderDetail → Refund → Ship → Review）+ IM 双页（Chat/ConversationList）+ 收藏/关注。每页对照 v1 报告「标准改造清单」执行。

**第三期（规范化，持续）**：
- 建立移动端组件规范：Select→大触控面板、Table→卡片列表、Modal→全屏/底部 Drawer、Descriptions→键值对列表；
- `global.less` 统一 safe-area 兜底；断点全部收敛到 `tokens.mq`；
- 管理后台明确策略：移动端只读兜底（表格横滚即可用）或访问时提示"请用桌面端"。

**验证方式**：桌面仿真只能发现布局问题，发现不了真机问题（此前"真机白底截断/遮罩丢失"两例即证明）。建议：本期修复后用真机过一遍 P0 链路，`logs/mobile-audit/` 截图作为回归基线，每次改动后重截对比。

## 九、第二轮审查（三期落地后全量回归，2026-09-25 19:20）

新增实测 10 页（r1~r10 截图）：知识库/文档/社区日报/社区管家/AI导购/模型管理/我的商品/我的主页/动态广场/搜索（含下拉交互）。

**结论：未发现新的 P0/P1 缺陷。**
- C 端新验证页（管家/导购/日报/我的商品/我的主页/动态广场）移动形态全部正常；
- 管理类页面（知识库/文档/模型）ProTable 横滚兜底可用，符合第三期"后台不做专门适配"策略；
- 代码扫描：Butler/ShoppingGuide 的 100vh 疑似项经核实为**误报**（JS 层 CSS.supports 已做 dvh 回退）；hover 依赖均为增强动效（卡片 tilt），无功能损伤。

**剩余低价值优化项（记录备查，暂不动）：**
1. 管理类表格操作列（修改/删除）触控偏小——受后台策略豁免；
2. AI 导购浮钮会遮挡卡片右下角文案——通用浮动按钮行为，可后续加半透明/缩小；
3. antd Select 下拉弹层为桌面样式——规范已定"整行+弹层"可接受。
