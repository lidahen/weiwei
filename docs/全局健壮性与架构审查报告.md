## 0. 一句话结论

**功能跑得通，但防线是纸做的。**

最高危的不是架构，而是三件很具体的事：**三个可被未授权访问的接口**、**一个已经进了版本库的云厂商密钥**、**Python 侧对身份头零校验**。这三样任何一个被扫到，损失都是直接的。

设计层面最大的债是三条：**伪微服务**（拆了 12 个模块却单进程跑、还互相直查对方的表）、**Python 双 ORM 直读同一个业务库**、**后端近乎零单测（12 个模块只有 1 个测试类）**——最后一条意味着前面所有修复都没有保护网。

## 4. 架构与设计不合理之处（规划部分）

分三类。**只把第 A 类当债还**，第 B 类是合理取舍、不要动。

### A. 真正的设计债（建议排期）

**A-1. 伪微服务：拆了 12 个模块，却单进程跑、还互相直查对方的表**
证据：`TradeOrderServiceImpl.java:8` 直接 `import com.twelvet.product.server.mapper.ProductMapper`；system / runner 模块同样跨模块直查。
代价：模块边界只剩心理约定——**无法独立部署伸缩，也拿不到微服务的任何收益，却付出了模块化的全部成本**（依赖管理、跨模块编译、循环依赖风险）。改 product 表结构要同步 trade。
判断：要么承认它是**模块化单体**并明确"模块间只准通过 Service 接口、禁止直查对方 Mapper"，要么真正拆开。当前是两头不靠，是最需要决策的一条。

**A-2. Python 直读业务库，形成双 ORM 映射同一批表**
证据：`ai-service/app/services/product_vector.py:135-138` 用 SQLAlchemy 原生 SQL 直读 `product` 表，与 Java `ProductMapper` 映射同一张表。
代价：schema 变更需 Java + Python **双端同步**；两套 ORM 定义必然漂移；且 Python 不继承 Sa-Token 鉴权与配额（`recommend` 明确不接 quota），**绕过了 Java 的安全与租户边界**——这正是 P0-4 的根因。
判断：这是为性能做的取舍（Python 直读避免多一跳），在单机部署下可接受，但**必须把 8001 限制在内网**，并把"共享的表结构"当作契约管理（建一个共享 schema 文档或由 Java 侧导出）。

**A-3. 后端近乎零单测**
证据：Java 测试类 **1 个**（`RecommendScorerTest.java`）对 12 个模块；Python 26 个；前端 2 个。
代价：前面所有修复（尤其多租户改造）**没有任何回归保护**。这是"重大任务"里优先级最高的一条——不是因为它最危险，而是因为**没有它，其余修复都不安全**。

**A-4. 全局 Jackson 配置的副作用**
证据：`JacksonConfiguration.java:36` 把 `Long` 全局序列化成 String；`application.yml:42` `default-property-inclusion: non_null` 全局丢弃 null。
代价：前端所有 Long 需 `Number()` 兜底防精度丢失；**null 键直接消失**，前端分不清"值为 0"、"空数组"与"后端没返回"，只能按 `undefined` 判断默认值（本次做信用分时就踩到：履约率为 null 时 `fulfillmentRate` 键整个不见了）。
判断：这两个配置本身是合理的技术决策（防 JS 精度丢失/减小报文），**问题在于它是全局隐式的、没有文档化**。建议在 README 或 CLAUDE.md 里显式写清这两条契约，而不是让人逐个踩坑。

**A-5. SQL 脚本治理失控**
证据：`backend/data` 27 个 + `backend/sql` 3 个 = **30 个增量脚本**；`neighborswap.sql` 有 **40 个 `CREATE TABLE` 没有 `IF NOT EXISTS`**（只有 1 个有）。
代价：**重跑即失败**，新环境初始化靠"按顺序手工执行"的记忆；`sys_menu` / `sys_role` 种子数据散落多个脚本，容易冲突；存在"加了列但实体类没同步"的错位风险。
判断：需要一次脚本基线化（把 30 个脚本收敛成 1 个可重复执行的 schema + 1 个种子脚本）。

### B. 可接受的取舍（不建议改，避免过度设计）

- 金额一律 `decimal(10,2)` —— 正确做法
- 推荐权重外置到 `application.yml` 的 `recommend.weights.*` —— 正确做法
- 召回多路合并走批量 `IN` + 内存归并，**未发现 N+1** —— 合理
- 状态字段用 `varchar` + 注释枚举 —— 有脏数据风险，但改 enum 成本高于收益，维持现状

### C. 缺失的能力（不是 bug，是"还没有"）

- **可观测性几乎为零**：没有告警、没有链路追踪，`AbstractQuartzJob` 吞异常后**没有任何人会知道任务挂了**
- **配置分散**：AI 服务地址散在 `AiGuideController.java:52` 字段 + `AiGuideWebClientConfig` + Python `settings`，改一处要动三处
- **幂等与对账**：支付有幂等（已确认），但退款、跑腿、AI 计费缺对账
